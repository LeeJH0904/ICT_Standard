| 분류 | 문서불일치 |
| 대상 | `CLAUDE.md` §0·§3.6·§9 · `docs/` |

| 상태 | 수정완료 |

## 근거

CLAUDE.md §0은 반드시 성립해야 하는 주장 4를 “표준의 실구현 장애 지점을 발견하고 해소했다”로 정하고 근거를 “`strict` / `extended` 모드 분리, `docs/standard-findings.md`”로 지정한다. §3.6은 “개발 착수 후 `docs/standard-findings.md`로 통합한다”고 정한다.

## 현상

`contracts/frame.py`의 strict/extended 분리는 존재하지만 `docs/`는 비어 있고 `docs/standard-findings.md`가 없다. 반면 인덱스의 표준결함 19건은 모두 `이관` 상태다. README.md §5에서 `이관`은 해당 파일로 옮겼다는 뜻이므로 상태와 산출물이 모순된다.

## 영향

`project_docs/`와 표준 원문은 제출물에서 제외된다. 현재 상태로 패키징하면 장애 지점 19건과 해소 근거가 제출물에서 사라져 네 핵심 주장 중 하나의 명시된 코드 근거가 존재하지 않는다.

## 재현

```text
Get-ChildItem docs -Force -> 출력 없음
CLAUDE.md:18  -> docs/standard-findings.md를 주장 4 근거로 지정
CLAUDE.md:241 -> 개발 착수 후 통합한다고 지정
bug_fix_list  -> 표준결함 19건 전부 이관
meta_verify   -> 88/88 통과
```

## 제안

설계 명세서 두 곳의 19건을 제출용 정본에 실제 통합하고 `이관` 상태와 대응 항목 존재를 메타 검증으로 연결해야 한다.
