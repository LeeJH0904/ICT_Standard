## 근거

공고문 `<소스코드 제출 안내>` 개인정보 보호(필수) — “제출물(소스코드·영상·문서)에는 실제 개인정보와 운영 중인 계정·비밀번호·API 키·접근토큰을 포함할 수 없으며”.

`fix_log/meta_verify.py:888-895`도 환경변수 이름만 언급한 코드는 실제 키 값이 아니므로 오탐 허용 대상으로 취급해야 한다고 명시한다.

## 현상

F-189가 추가한 다음 안전한 코드 5곳을 `SECRET` 정규식이 비밀값으로 분류한다.

```text
config.py:15  KMA_API_KEY,
config.py:16  OPENAI_API_KEY,
mms.py:144    api_key = os.getenv(OPENAI_API_KEY, ").strip()
mms.py:146    if not api_key or not model:
mms.py:148    if (len(api_key) > 4096 ...
```

실제 값은 없고 런타임 조회 변수명뿐이다. 제출본 실제 키 패턴 검사와 `.env` 부재도 별도로 확인했지만 `python fix_log/meta_verify.py`는 `117/119`와 종료코드 1을 반환한다.

## 영향

F-189 구현 직전 `119/119`였던 검증 출구가 새 기능을 정상 구현한 것만으로 실패한다. 실제 비밀값 유무와 무관한 오탐 때문에 최종 무결성 판정을 통과할 수 없으며, 이후 작업자가 경고를 무시하거나 검증기 전체를 우회할 위험이 생긴다.

## 재현

```powershell
python fix_log/meta_verify.py
# FAIL 금지 - 비밀정보·개인식별 패턴 없음
# ['config.py:15', 'config.py:16', 'mms.py:144', 'mms.py:146', 'mms.py:148']
# 117/119 통과, exit 1
```

## 제안

기존 KMA 환경변수 허용 목록과 같은 원칙으로 파일·문맥이 고정된 환경변수 이름 및 `os.getenv()` 조회만 좁게 허용한다. 실제 값이 대입된 반례는 계속 실패하는 결함 주입 테스트를 함께 추가한다.
