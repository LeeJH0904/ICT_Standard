## 근거

F-089는 독립 입력 대조, F-090은 문서 수치 전수 대조를 회귀검사로 고정했다고 처리됐다. 현재 전체 실행은 API 60/60, 웹 55/55, 서비스 37/37, 메타 47/47로 모두 통과한다.

## 현상

통과 상태에서 F-091~F-094의 반례와 드리프트가 실재한다.

- API 검증기는 `if/then`, `oneOf`, `minProperties`, 속성 이름의 존재만 보고 실제 JSON Schema 반례를 주입하지 않는다. nullable 필수값·응답 required 누락·422 부재가 전부 통과한다.
- 웹 검증기는 F-083·F-085 필드의 존재만 보고 상태별 필수성을 검사하지 않으며, A.1-5 판정과 부속서 집계를 서비스 대조표와 교차하지 않는다.
- 웹 검증기는 “쓰기 4→5” 문구 자체를 PASS 조건으로 고정했지만 현재 쓰기 7건과의 시점 관계는 검사하지 않는다.
- 서비스 검증기는 본문의 집계표는 재계산하지만 §4.5·§5의 `⚠ 7건`, 쓰기 4건, 테스트 76종, A.1-5 종결 주장을 검사하지 않는다.
- 메타 검증의 F-090 검사는 아키텍처·화면 문서에서 정규식 `쓰기 N건`만 찾는다. 서비스 대조표를 대상에서 제외하고 `4 → 5` 같은 표기도 잡지 않아 47/47이 된다.

독립 결함 주입으로 `injectVector`, `Frame.fields`, `set_device_property`를 각각 제거했을 때 웹 검증기는 모두 exit 1로 뒤집혔다. 따라서 F-089의 핵심 연결 검사는 살아 있지만, 새 의미 불변식과 F-090 전수성은 커버되지 않는다.

## 영향

수정완료 선언의 근거인 녹색 회귀 결과가 실제 계약 완결성과 문서 무결성을 보장하지 않는다. 같은 형태의 nullable·조건부 필수·본문 수치 드리프트가 이후에도 재발할 수 있다.

## 제안

API 검증기에 실제 JSON Schema validator로 정상/반례 매트릭스를 넣고, DB에는 F-091의 세 SQL 반례를 추가한다. 웹·서비스 검증기는 A.1-5와 부속서 집계를 교차하고, 메타 검증은 `project_docs/**/*.md` 전체에서 현재 수치와 역사적 수치를 구분해 검사한다. F-091~F-094를 하나씩 되돌리는 결함 주입이 각각 해당 검증기를 실패시키는지 확인한다.
