# F-134 · 표준 미규정 결정의 이관 규칙이 정본과 충돌

| 항목 | 값 |
|---|---|
| 심각도 | 오류 |
| 분류 | 문서불일치 |
| 대상 | `CLAUDE.md` §3.5 · `project_docs/firmware/펌웨어_설계서.md` §9 · `docs/standard-findings.md` |
| 발견일 | 2026-08-09 |
| 상태 | 수정완료 |

## 근거

`fix_log/README.md` §3·§5는 `표준결함`만 `docs/standard-findings.md`로 이관하며, 상태 `이관`도 그 이동만 뜻한다고 정한다. 같은 문서 §6은 해당 파일을 표준결함의 최종 정본으로 지정한다.

`CLAUDE.md` §3.6도 표준결함 19건을 `docs/standard-findings.md`로 통합한다고 정하고, §11.3은 분류 `표준결함`의 처리만 그 파일로 이관하도록 정한다.

## 현상

F-130 정본화는 샘플링 주기·Both 제약·Period=0을 `표준 미규정 사항` 3건으로 `CLAUDE.md` §3.5와 펌웨어 설계서 §9에 추가했다. 그러나 `CLAUDE.md` §3.5 말미는 새 미규정 사항을 `docs/standard-findings.md`에 추가하라고 하고, 펌웨어 설계서 §9 말미도 표의 9행을 그 파일로 이관하라고 명령한다.

실제 `docs/standard-findings.md`와 `fix_log/meta_verify.py`는 표준결함 19건만 허용한다. 미규정 결정 9건은 이관되지 않았으며, 이관하면 메타 검증의 “파일이 언급하는 F-ID가 이관 표준결함 집합과 정확히 일치” 검사가 실패한다. F-130 처리 기록도 해당 파일을 “표준결함 전용”으로 판정해 현행 §3.5·§9 문구와 정면으로 어긋난다.

## 영향

개발자가 표준 미규정 결정을 어디에 기록해야 하는지 정본이 둘로 갈린다. 현재 상태를 따르면 문서의 이관 명령을 위반하고, 명령을 따르면 `README.md` 기록 규약과 메타 검증을 위반한다. 따라서 F-130의 정책 내용은 기록됐지만 기록 위치 규약까지 포함한 정본화 완료 주장은 성립하지 않는다.

## 재현

```text
CLAUDE.md §3.5: 새 미규정 사항 -> docs/standard-findings.md에 추가
펌웨어 설계서 §9: 미규정 결정 9행 -> docs/standard-findings.md로 이관
fix_log/README.md §3·§5·§6: 표준결함만 해당 파일로 이관
fix_log/meta_verify.py: 해당 파일의 F-ID 집합 == 이관 표준결함 집합
실제 docs/standard-findings.md: 표준결함 19건만 존재
```

## 제안

`docs/standard-findings.md`를 표준결함 전용 정본으로 유지한다면 `CLAUDE.md` §3.5와 펌웨어 설계서 §9의 이관 명령을 제거하고, 미규정 결정은 `CLAUDE.md` §3.5 및 각 설계서의 결정 표에 기록한다고 명시한다. 반대로 한 파일에 두 분류를 모두 담으려면 `README.md`, 문서 구조, 상태 의미, 메타 검증을 함께 바꾸고 두 분류를 명확히 분리해야 한다.
