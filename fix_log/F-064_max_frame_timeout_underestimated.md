# F-064 · 최대 프레임을 51byte로 가정해 응답 타임아웃 근거가 틀림

| 항목 | 값 |
|---|---|
| 심각도 | 오류 |
| 분류 | 문서불일치 |
| 대상 | `project_docs/arch/아키텍처_설계서.md:493-500`, 골든 벡터 B03, 0943 표 7-15~7-17 |
| 발견일 | 2026-08-05 |
| 상태 | 수정완료 |

## 근거

0943 헤더의 `Payload Length`는 16bit다. 표 7-15는 `DEVICE_PROPERTY`를 240bit(30byte), 표 7-16은 이를 N개 연접하도록 정의하며, 표 7-13의 `Num. of Devices`도 8bit다.

새 골든 B03 자체가 `DEVICE_ID×255`를 담은 **267byte 프레임**이다.

## 현상

아키텍처 §6.2는 `Message Receive Timeout` 최소 1초의 근거로 "9600 baud에서 최대 프레임 51byte ≈ 53ms"라고 적는다. 51byte는 `DEVICE_PROPERTY` 한 건 정도만 넣은 경우일 뿐 가변 N의 최대가 아니다.

연결 응답 `RSC(1)+NODE_PROPERTY(8)+DEVICE_PROPERTY(30)×255`는 헤더 포함 7,671byte다. 같은 8N1 산식으로 9600 baud 전송에 약 **7.99초**가 걸린다. 골든 기본 프로파일의 timeout 2초도 이 범위를 수용하지 못한다.

## 영향

다수 디바이스 노드에서는 정상 응답이 끝나기 전에 요청이 타임아웃·재전송될 수 있다. "노드 추가 시 서버 코드 수정 0줄" 확장성 주장과 메시지 흐름 안정성에 직접 영향을 준다.

## 제안

지원할 N의 상한 또는 최대 프레임 크기를 명시하고, baud rate와 최대 wire time에서 timeout 하한을 도출한다. 골든 경계에도 가장 큰 요소 크기의 N 최대 프레임을 포함한다.
