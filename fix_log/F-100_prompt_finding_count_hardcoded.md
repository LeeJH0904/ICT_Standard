## 근거

개발 착수 지시서 §0.1 — 현재 단계를 파일에 적어 두지 않는다. 상태 파일은 갱신을 빠뜨리는 순간 실제와 갈린다.

`CLAUDE.md` §6.2의 F-094 규칙 — 검사 대상을 열거하지 않고 디렉터리 전수로 보며, 역사적 수치가 아닌 현재 주장은 실측과 대조한다.

## 현상

사람용 검증 프롬프트가 기존 발견 수 `92`와 마지막 ID `F-096`을 현재값으로 하드코딩한다. 이번 검증에서 규약대로 F-097~F-099를 추가한 직후 `dev_verify.py`가 다음 두 항목에서 실패했다.

- 프롬프트 기존 발견 건수 92와 인덱스 95 불일치
- 프롬프트 ID 끝 F-096과 인덱스 F-099 불일치

이 불일치를 F-100으로 기록한 직후 값도 96건·F-100이어서 같은 두 검사는 계속 실패했다. 검증자가 수정할 수 있는 `fix_log/`에 정상적으로 행을 추가하는 행위만으로 전체 회귀가 필연적으로 깨지는 구조다.

F-094는 웹·서비스·API 설계 문서의 완료 수치 드리프트를 다뤘다. 이 건은 당시 대상이 아니었던 호출용 프롬프트의 동적 인덱스 수치 하드코딩이므로 같은 지적의 반복이 아니다.

## 영향

모든 독립 검증 회차가 신규 발견을 기록하는 순간 `run_all.py`를 9/10 실패로 만든다. 실제 구현 회귀와 정상적인 인덱스 증가를 구분할 수 없고, 사람용 프롬프트를 매번 수동 갱신해야 한다.

## 제안

프롬프트에는 고정 건수·마지막 ID 대신 `bug_fix_list.md` 상단의 다음 ID와 실제 행을 읽으라고만 적는다. `dev_verify.py`는 그 동적 지시의 존재를 검사하고 특정 숫자 일치를 요구하지 않는다.
