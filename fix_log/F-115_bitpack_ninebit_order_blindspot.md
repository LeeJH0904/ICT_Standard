## 근거

펌웨어 설계서 §4.1(`project_docs/firmware/펌웨어_설계서.md:292`)은 `bitpos` 0이 바이트 최상위 비트인 **MSB-first**를 계약으로 정한다. 개발 착수 지시서 §3.2는 바이트 경계를 넘는 9bit 쓰기를 신설 테스트의 필수 항목으로 지정한다.

## 현상

F-112 수정으로 비정렬 9bit 호출은 추가됐지만 검사는 같은 구현의 `bp_write`로 쓴 값을 같은 구현의 `bp_read`로 되읽는 왕복과 “버퍼가 0이 아닌가”만 본다. 독립 기대 바이트열은 확인하지 않는다.

비정렬 `nbits==9` 경로에서만 `bp_write`를 LSB-first로 기록하고 `bp_read`도 같은 LSB-first로 읽도록 임시 변형했다. `val=0x1A5`, `bitpos=5`의 정본 MSB-first 결과는 `06 94 00 00`이지만 변형은 `05 2C 00 00`을 만든다. wire 바이트가 틀렸는데도 서로 역연산이므로 원본 테스트는 **39/39, exit 0**이었다.

F-112의 기존 두 반례는 같은 실행에서 각각 37/39로 차단됨을 별도로 확인했다. 이 건은 “아무것도 쓰지 않는 9bit” 재보고가 아니라, 왕복 자기검증이 놓치는 비트 배열 오류다.

## 영향

9bit 필드만 설계와 반대 순서로 직렬화·역직렬화하는 구현이 단계 2a 출구를 통과한다. 동일한 잘못을 가진 로컬 writer/reader끼리는 동작하지만 다른 SIAP 구현과 wire 상호운용되지 않는다.

## 재현

1. `bitpack.c`의 비정렬 9bit 분기에만 LSB부터 순서대로 쓰는 코드를 주입한다.
2. `bp_read`의 같은 분기에 LSB부터 복원하는 역연산을 주입한다.
3. 원본 `test_bitpack.c`와 실제 CFLAGS로 컴파일·실행한다.
4. 실제 결과: 컴파일 경고 0, **39/39**, exit 0.
5. 독립 산술 결과: 정본 MSB-first `06940000`, 결함 LSB-first `052C0000`.

## 제안

case2b에서 왕복 외에 전체 기대 바이트열 `06 94 00 00`을 독립 상수로 대조한다. writer와 reader를 함께 같은 방향으로 잘못 바꾸는 결함 주입이 실패로 반전되는지 고정한다.
