# F-098 · where.py가 단계 2c·7·8의 필수 출구를 실행하지 않음

| 항목 | 값 |
|---|---|
| 심각도 | 오류 |
| 분류 | 코드버그 |
| 대상 | `tools/where.py:165-175,229-239` |
| 발견일 | 2026-08-08 |
| 상태 | 수정완료 |

## 근거

개발 착수 지시서 §0.1 — 출구 명령을 순서대로 돌려 처음 실패하는 단계가 현재 단계다.

같은 문서 §3.4의 단계 2c 출구는 `project_code/firmware/tests` 4종 전량을 `make && ./test_*`로 실행한다. §3.9는 headless 스크린샷 4장 렌더 확인, §3.10은 3종 빌드와 `avr-size`, 실측 로그의 replay를 필수 출구로 둔다.

## 현상

`where.py`는 이 출구들을 실행하지 않는다.

- 단계 2c는 기존 `test_node_state` 실행파일 한 개와 `firmware_verify.py`만 실행한다. `make`와 테스트 4종 전량 재실행이 없다.
- 단계 7은 `web_verify.py`와 `web_live_verify.py`만 실행하고 렌더 4장을 확인하지 않는다.
- 단계 8은 `board_verify.py`만 실행하고 별도 출구인 3종 빌드·`avr-size`·실측 로그 replay를 직접 확인하지 않는다.

성공하는 오래된 바이너리를 메모리 주입한 직접 호출에서 단계 2c의 실행 명령은 `test_node_state` 하나뿐이었다. 단계 7·8의 결과 목록도 각각 2개와 1개뿐이었다.

빈 임시 저장소에서 오류 없이 단계 0과 종료 코드 0을 출력하는 추가 요구는 별도로 통과했다.

## 영향

후속 단계에서 필수 빌드·렌더·실측 replay가 실패하거나 실행되지 않았는데도 더 뒤 단계를 현재 단계로 판정할 수 있다. 현재 단계 도출이라는 스크립트의 핵심 계약이 깨진다.

## 재현

1. `Path.exists`와 `_run`이 성공하는 오래된 `test_node_state`를 반환하도록 메모리 주입한다.
2. `check_stage_2c()`, `check_stage_7()`, `check_stage_8()`을 직접 호출한다.
3. 실제 2c 실행 목록: `test_node_state` 한 건. `make` 없음.
4. 실제 단계 7 결과: 검증기 2건뿐. 렌더 없음.
5. 실제 단계 8 결과: `board_verify.py` 한 건뿐. 빌드·replay 없음.

## 제안

상세 절의 출구를 그대로 실행하고 빌드 산출물은 매번 소스에서 재생성한다. 자동화할 수 없는 항목은 통과로 간주하지 말고 검증 불가로 남긴다.
