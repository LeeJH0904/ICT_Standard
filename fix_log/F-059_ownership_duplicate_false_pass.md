## 근거

1369-P1 7.2.2·7.2.3은 설정형·측정형 데이터와 관계 데이터의 서로 다른 생명주기를 정의한다.

아키텍처 §4.4-a는 "31개 테이블 전부가 **정확히 하나의 소유자**를 갖는다"고 선언한다. F-057 처리 기록도 표의 완결성을 자동 검사로 고정했다고 명시한다.

## 현상

`meta_verify.py`는 §4.4-a 전체에서 발견한 백틱 테이블명을 하나의 `set`으로 합친 뒤 `TABLES - owned`만 검사한다. 같은 테이블이 두 분류에 있어도 set에서 하나로 합쳐지므로 중복을 알 수 없다. 또한 표의 분류별 실제 개수를 세지 않고 문서에 적힌 `9 + 19 + 2 + 1 = 31` 문자열만 계산한다.

실제 문서를 메모리에서 변형해 시드 로더의 `control_model`을 API 스레드 표에도 중복 추가했지만 메타 검증은 **27/27, 종료코드 0**으로 통과했다.

## 영향

F-057의 핵심 불변식인 "정확히 하나" 중 누락만 검사하고 중복은 검사하지 않는다. 서로 다른 스레드가 같은 테이블의 쓰기 소유자라고 문서화돼도 자동 검증은 성공한다.

## 재현

```text
1. 아키텍처 §4.4-a에서 control_model을 시드 로더에 둔 채 API 스레드 표에도 추가한다.
2. 표기된 합계 문구 9 + 19 + 2 + 1 = 31은 그대로 둔다.
3. meta_verify.py를 실행한다.
4. 쓰기 소유권 검사와 전체 결과가 27/27, exit 0으로 통과한다.
```

## 제안

소유권 분류별 표 행을 별도로 파싱해 각 테이블의 출현 분류 수가 정확히 1인지 확인하고, 분류별 실제 고유 테이블 수를 9·19·2·1과 대조한다.
