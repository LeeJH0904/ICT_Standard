# F-075 · bp_write의 비트폭 초과 방지 계약이 호출자에게 열려 있음

| 항목 | 값 |
|---|---|
| 심각도 | 위험 |
| 분류 | 문서불일치 |
| 대상 | `project_docs/firmware/펌웨어_설계서.md:226-244` |
| 발견일 | 2026-08-05 |
| 상태 | 수정완료 |

## 근거

0943 표 7-6은 Message Type 14bit·Transmission Type 2bit, 표 7-8은 GCG ID와 Node ID를 각각 20bit로 제한한다.

프로젝트 규약 F-044는 비트폭 초과를 조용히 마스킹·래핑하지 않고 거부하도록 확정했다.

## 현상

`bp_write(uint8_t*, size_t*, uint32_t, uint8_t)`는 반환값이 `void`다. 설계서는 범위 초과를 함수가 아니라 "호출 전에 검사"한다고만 적고, 어떤 계층이 어떤 필드를 검증하는지나 `siap_node_init`의 ID·device_count 검증 계약을 닫지 않았다.

따라서 호출 한 곳이 검사를 빠뜨리면 14bit/20bit보다 큰 값의 하위 비트만 wire에 기록되어도 호출자가 실패를 알 방법이 없다. 현재는 구현 전이라 실제 누락 여부를 판정할 수 없지만, API 자체가 F-044 불변식을 강제하지 않는다.

## 영향

보드별 바인딩이나 향후 메시지 추가 시 한 번의 검증 누락이 서로 다른 ID·Message Type으로 조용히 전송될 수 있다. 골든 고정값 테스트만으로 런타임 설정값 경계를 보장하지 못한다.

## 제안

비트 writer가 성공/실패를 반환해 폭 검사를 직접 강제하거나, 모든 진입점의 필드별 범위 검증표와 초과 반례 테스트를 설계 계약에 추가한다.
