# F-129 · PROGMEM SRAM 예산 주장과 static const 구현이 모순

| 항목 | 값 |
|---|---|

| 발견일 | 2026-08-08 |
| 상태 | 수정완료 |

## 근거

CLAUDE.md §1-5·§4.2는 `core/`의 보드별 수정과 `avr/*` include를 금지한다. 개발 착수 지시서 §1.5는 `avr-size` 실측이 설계 추정치를 대체한다고 정한다. 0943 원문은 MCU의 상수 저장 위치를 규정하지 않는다.

## 현상

펌웨어 설계서 §3.5는 34종 LAYOUT 테이블을 `PROGMEM`에 두어 SRAM을 쓰지 않는다고 예산을 계산하고, §5.3은 `pgm_read_byte()`를 쓴다. 실제 `siap_types.h`는 `SIAP_WIRE_CODE` 2종과 `SIAP_LAYOUT`을 일반 `static const` 배열로 두며 AVR에서 RAM에 놓일 수 있다고 주석으로 명시한다. `siap_frame.c`도 배열을 직접 읽는다.

표준 원문은 저장 방식을 결정하지 않는다. 프로젝트 규약상 플랫폼 무관 구현이 옳고, 설계서의 PROGMEM 전제와 SRAM 표가 현재 구현을 잘못 설명한다.

## 영향

51 byte 윈도우는 지켜지지만 전체 SRAM 예산은 입증되지 않는다. 설계서가 SRAM 0으로 계산한 테이블이 실제 AVR에서 RAM을 쓰면 §3.4 예산과 40% 상한 근거가 달라진다. `firmware_verify.py 50/50`은 이 불일치를 놓쳤다.

## 재현

- 설계서에서 `PROGMEM|pgm_read_byte`를 검색한다.
- 구현에서 `static const|SIAP_LAYOUT[k]`를 검색한다.
- 현 환경에는 `avr-gcc`·`avr-size`가 없어 실제 AVR `.data/.bss` 수치는 검증 불가.

## 제안

설계서와 예산을 현재 구현에 맞추고, `avr-size` 실측 전에는 SRAM 0을 현재 사실로 주장하지 않는다.
