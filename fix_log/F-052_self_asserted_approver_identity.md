# F-052 · 승인자 식별자가 자체 주장 헤더에 불과함

| 항목 | 값 |
|---|---|

| 분류 | 문서불일치 |
| 대상 | `project_docs/api/API_명세서.md` §2.1, `openapi.json:926-934` |
| 발견일 | 2026-08-03 |

## 근거

0937 부속서 A §3.2 절차 3 — "사용자는 최종 의사결정 후 제어 조건 조정을 한다."

API 명세서는 인증을 범위 밖으로 두고 `X-User-Id` 문자열만 승인자로 기록한다.

## 현상

OpenAPI에는 인증 `securitySchemes`와 보안 요구가 없고, 승인 호출자가 임의의 `X-User-Id`를 직접 지정한다. DB 외래키는 그 ID가 존재하는지만 검사하므로 기존 사용자 ID를 넣으면 실제 호출자가 그 사용자인지는 확인할 수 없다.

## 영향

승인 기록은 “이 문자열이 제출됐다”는 무결성만 증명하고 “그 사람이 최종 결정했다”는 사실은 증명하지 못한다. 현재 localhost 데모 범위에서는 수용할 수 있으나, 기획서·발표에서 사람 승인 증거를 강하게 주장하면 반박 지점이 된다.

## 제안

인증을 계속 범위 밖으로 둘 경우 승인자 신원은 보장하지 않는다는 한계를 핵심 주장과 시연 설명에도 명시한다. 실제 서비스 가능성을 주장하려면 최소한 세션 기반 사용자 확인이 필요하다.
