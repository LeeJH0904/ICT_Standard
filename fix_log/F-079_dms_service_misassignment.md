# F-079 · 노드 속성 설정이 0937 6.2 DMS 로 잘못 배정됨

| 항목 | 값 |
|---|---|
| 심각도 | 오류 |
| 분류 | 문서불일치 |
| 대상 | `project_docs/arch/아키텍처_설계서.md` §3.1 `handle()` |
| 발견일 | 2026-08-07 |
| 상태 | 수정완료 |

## 근거

TTAK.KO-10.0937 **6.2 데이터관리서비스(DMS)** — *"데이터관리서비스는 **공공데이터(Public Data)
서비스로부터 필요한 외부 데이터를 수집하여 데이터베이스에 기록하는 서비스**이다."*

TTAK.KO-10.0937 **6.1 장치관리서비스(EMS)** — *"장치관리서비스는 농장에 설치되어 있는 클라우드용
센서노드(C-SN), 구동기노드(C-AN), 복합노드(C-HN), 통합제어기(C-GC), 게이트웨이(C-GW) 등의
**설치, 변경, 삭제 및 자동화된 연결을 지원하고, 장치의 상태 및 운영 정보를 수집**하는 서비스이다."*

0937 6.1 세부 요구사항 2 — *"클라우드 기반 센서노드 및 구동기노드 등 장치들의 **구동 주기 및 오류
관리**가 가능해야 한다."*

## 현상

아키텍처 §3.1 의 `handle()` 이 노드·디바이스 속성 설정 3종을 `dms` 에 배정했다.

```python
case MsgKind.REQ_SET_NODE_PROPERTY:                    # 8.1.3.1
    return build.res_set_node_property(frame, dms.on_node_property(frame))
case MsgKind.REQ_SET_DEVICE_PROPERTY:                  # 8.1.3.2
    return build.res_set_device_property(frame, dms.on_device_property(frame))
case MsgKind.REQ_SET_NODE_DEVICE_PROPERTY_ALL:         # 8.1.3.3
    return build.res_set_node_device_property_all(frame, dms.on_node_device_all(frame))
```

같은 문서 §7 은 `dms` 를 공공데이터 경로에도 쓴다 — *"[dms] 기상청 API 또는 fixtures/ ──>
public_data_record 저장"*. 즉 **`dms` 하나가 서로 다른 두 조항의 일을 겸하고 있었고, 그중 하나는
0937 이 정의한 DMS 의 범위 밖이다.**

특히 `DEVICE_PROPERTY`(표 7-15)의 `Period` 는 **6.1-2 가 명시한 "구동 주기 관리"** 그 자체다.

## 영향

`backend/services/` 를 아키텍처 문서대로 구현하면 **0937 조항과 모듈이 어긋난 채 코드가 굳는다.**
이 프로젝트에서 0937 의 준수 근거는 조항 대 구현의 대조표뿐이므로(0943 의 골든 벡터, 1369-P1 의
스키마 제약에 해당하는 실행 가능한 근거가 0937 에는 없다), **배정이 틀리면 표준 활용성 30점 항목의
근거 문서 자체가 틀린 것이 된다.**

발표 질의에서 "DMS 가 왜 노드 속성을 다루는가"를 받으면 답할 근거가 없다.

## 재현

```text
project_docs/arch/아키텍처_설계서.md 의 handle() 에서 dms.on_node_property 를 찾는다.
TTAK.KO-10.0937.md 6.2 의 정의문과 대조한다.
→ 공공데이터 수집 서비스가 노드 속성 설정을 처리하고 있다.
```

## 제안

세 진입점을 `ems` 로 옮기고, `dms` 는 공공데이터 전용으로 남긴다.
