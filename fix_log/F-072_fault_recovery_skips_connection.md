# F-072 · 부팅 진단 실패 후 복구가 연결 승인을 우회함

| 항목 | 값 |
|---|---|
| 심각도 | 오류 |
| 분류 | 문서불일치 |
| 대상 | `project_docs/firmware/펌웨어_설계서.md:477-506,510-529` |
| 발견일 | 2026-08-05 |
| 상태 | 수정완료 |

## 근거

0943 8.1.1 — `REQ_SET_CONNECTION`은 노드가 단일 GCG와 "조회, 설정, 알림 등 기능을 운용"하기 위한 **초기 연결승인 절차**다.

## 현상

전이표는 `INIT`의 자가진단 실패를 `FAULT`로 보내고, 모든 `FAULT`의 오류 해소를 무조건 `RUNNING`으로 보낸다. 따라서 부팅 직후 진단에 실패한 노드는 `CONNECTING`과 `RES_SET_CONNECTION(RSC=SUCCESS)`를 한 번도 거치지 않고 복구 즉시 조회·설정·알림 기능을 수행한다.

같은 `FAULT`는 이미 연결된 `RUNNING`에서 장치 오류가 난 경우에도 사용된다. 연결 전·후 상태를 하나로 합친 뒤 복귀 목적지를 하나로 고정한 것이 원인이다. 초기 진단 실패 중에는 연결 승인 전인데도 `NOTI_ERROR`를 주기 송신한다.

## 영향

GCG가 노드 등록을 거부했거나 속성 프로파일을 아직 내려주지 않은 상태에서 노드가 정상 운용을 시작할 수 있다. 설계가 자체적으로 둔 "연결 전에는 DEVICE_PROPERTY가 없어 요청을 처리할 수 없다"는 이유와도 충돌한다.

## 제안

연결 전/후 FAULT를 구분하거나 `connected` 이력을 보존한다. 부팅·연결 전 FAULT의 복구 목적지는 `CONNECTING`, RUNNING에서 진입한 FAULT의 복구 목적지만 `RUNNING`이어야 한다.
