# F-103 · offline_verify가 세 정책 위반을 동시에 거짓 통과

| 항목 | 값 |
|---|---|
| 심각도 | 오류 |
| 분류 | 코드버그 |
| 대상 | `tools/offline_verify.py:72-105,196-225` |
| 발견일 | 2026-08-08 |
| 상태 | 수정완료 |

## 근거

아키텍처 설계서 §8.3은 `requirements.txt`의 직접 의존성 3개를 `==`로 고정하고, 전이 의존성은 `wheels/`에 패키지당 정확히 한 버전만 두어 휠 집합 자체가 잠금 역할을 하도록 정한다.

개발 착수 지시서 §3.0과 `CLAUDE.md` §2.1은 제외 대상이 실제 `.gitignore` 규칙과 패키징에서 빠져야 한다고 정한다.

## 현상

임시 제출물에 다음 세 위반을 동시에 주입했다.

1. 직접 의존성을 `fastapi>=0.115.6`, `uvicorn>=0.34.0`, `pyserial~=3.5`로 바꾸어 `==` 고정을 제거했다.
2. `click` 휠을 다른 버전 파일명으로 하나 더 넣어 패키지당 버전 후보를 2개로 만들었다.
3. `.gitignore`의 `.omc/` 뒤에 `!.omc/`를 넣었다. 실제 `git check-ignore --no-index .omc/probe.txt`는 종료 코드 1, 즉 제외되지 않음이었다.

그런데 `offline_verify.py`는 직접 의존성 이름 집합만 비교하고, 휠의 패키지별 버전 유일성을 세지 않으며, `.gitignore` 규칙의 순서와 `!` 재포함 의미를 해석하지 않는다. 결과는 6개 플랫폼 설치를 포함한 다섯 항목 전부 OK와 종료 코드 0이었다.

F-097의 기존 반례였던 네 번째 의존성, 주석뿐인 규칙, `.git/` 패키징 누락은 이번 재검증에서 모두 차단됐다. 이 건은 그 수정이 다루지 않은 버전 지정자·중복 후보·부정 패턴 의미론의 새 반례다.

## 영향

검증기가 통과해도 직접 의존성 버전과 전이 버전이 재현 가능하게 잠기지 않을 수 있고, 제출 제외 대상이 실제 Git 의미론에서는 다시 포함될 수 있다. F-099에서 정정한 오프라인 잠금 전략을 출구 검사가 보장하지 못한다.

## 재현

1. 실제 `wheels/`를 임시 디렉터리에 복제한다.
2. 위 세 위반을 주입하고 `.omc/probe.txt`를 만든다.
3. `git check-ignore --no-index .omc/probe.txt`가 종료 코드 1인지 확인한다.
4. 임시 루트를 가리키도록 검증기를 실행한다.
5. 실제 결과: 휠 20개, 6개 플랫폼 설치 성공, 다섯 검사 전부 OK, 종료 코드 0.

## 제안

요구사항 각 유효 행이 허용된 이름과 정확한 `==` 지정자를 갖는지 파싱한다. 휠은 정규화한 배포명별 버전 집합이 정확히 하나인지 검사하되 같은 버전의 플랫폼·ABI별 파일은 허용한다. `.gitignore`는 가능하면 임시 Git 저장소의 `git check-ignore`로 실제 최종 의미를 확인하거나 최소한 순서와 `!` 재포함을 구현한다.
