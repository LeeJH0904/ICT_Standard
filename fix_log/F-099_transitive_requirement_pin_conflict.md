# F-099 · 전이 의존성 requirements 고정 문구가 3개 의존성 정본·구현과 충돌

| 항목 | 값 |

| 분류 | 문서불일치 |

| 상태 | 수정완료 |

## 근거

공고문 3장 소스코드 제출 안내 — 전체 소스코드는 200MB 이하이며 압축파일만으로 실행 가능해야 하고, 제출물만으로 실제 실행을 재현할 수 있어야 한다.

`CLAUDE.md` §4.3 — 의존성은 `fastapi` · `uvicorn` · `pyserial` 3개이며 추가 전 사용자 확인이 필요하다.

아키텍처 §8.1도 직접 의존성은 3개라고 정하지만, §8.3은 `requirements.txt`를 전이 의존성까지 `==`로 고정한다고 적는다.

## 현상

실제 `requirements.txt`에는 직접 의존성 세 개만 `==`로 고정되어 있고 전이 의존성은 없다. 이는 개발 규약과 단계 0 추가 지시에는 맞지만 아키텍처 §8.3과는 맞지 않는다.

상위 정본인 공고문은 전이 의존성을 어느 파일에 적을지 정하지 않고 실제 재현 가능성만 요구한다. 현재 구현은 격리된 Windows Python 3.13 설치와 Windows/Linux × Python 3.11~3.13 여섯 조합의 `--no-index` 설치를 모두 통과했다. 따라서 구현과 직접 의존성 3개 규약이 옳고, 아키텍처 §8.3의 파일 구성 설명이 틀리다.

## 영향

후속 작업자가 §8.3을 문자 그대로 따르면 전이 패키지까지 요구사항에 추가해 직접 의존성 3개 규약과 충돌한다. 반대로 현재 파일만 보면 전이 버전 고정이 `wheels/`의 단일 후보에 의존한다는 전략이 문서에서 불분명하다. 지금은 설치되지만 갱신 때 재현 전략이 갈릴 위험이 있다.

## 제안

`requirements.txt`에는 직접 의존성 3개만 둔다는 정본을 유지하고, 전이 버전은 별도 잠금 파일 또는 `wheels/`의 단일 버전 집합으로 고정한다는 실제 전략을 §8.3에 명시한다.
