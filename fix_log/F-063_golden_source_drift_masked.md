# F-063 · 골든 정본과 생성물의 드리프트를 검사하지 않고 실행 중 덮어씀

## 근거

CLAUDE.md §6.2 — "`golden.jsonl`을 직접 편집하지 않는다. 정본은 `golden_layout.py`의 레이아웃이다."

공고문 3장 소스코드 제출 안내 — 제출물만으로 실제 실행과 재현이 가능해야 한다. 검증 결과가 실행 전 파일 상태를 보존하고 판정해야 재현 증거가 된다.

## 현상

`golden_verify.py`는 정본인 `golden_layout.py`를 읽거나 그 출력과 JSONL을 비교하지 않는다. 정본만 바꾸고 생성하지 않으면 stale `golden.jsonl`을 검증해 성공한다.

반대로 메타 검증은 `VERIFIERS`에서 `golden_layout.py`를 `golden_verify.py`보다 먼저 실행한다. 생성기는 검증기가 아니라 JSONL 두 파일을 무조건 덮어쓰는 프로그램이므로, 생성물이 변질되거나 stale이어도 메타 검증이 먼저 복구한 뒤 34/34를 출력한다.

## 영향

검증 전에는 정본과 생성물이 달랐다는 사실이 사라지고, 자동 검증은 그 드리프트를 발견하지 못한다. 제출된 `golden.jsonl`이 실제 손작성 정본에서 나온 것인지 증명할 수 없다.

## 재현

```text
A. golden_layout.py만 바꾸고 golden_verify.py 실행 → 기존 JSONL을 검사해 통과 가능
B. golden.jsonl만 변형하고 meta_verify.py 실행 → golden_layout.py가 먼저 덮어쓴 뒤 통과
```

## 제안

정본을 읽기 전용으로 평가해 메모리 또는 임시 경로에서 JSONL을 생성하고, 체크인된 생성물과 byte-for-byte 비교한다. 메타 검증의 자식 목록에서는 상태를 변경하는 생성기를 분리한다.
