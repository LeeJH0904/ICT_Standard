# F-124 · F-120의 N=16 분기와 53건 골든이 지정 문서에 미반영

| 항목 | 값 |

## 근거

0943 표 7-13은 `Num. of Devices`를 8bit로 두어 표준 자체는 N=255까지 연다. 프로젝트 정본은 CLAUDE.md §3.5의 “노드당 디바이스 상한 N=16”이며 F-120 처리로 Python/C가 N>16을 거부하고 B11이 추가되어 골든은 53건이 됐다.

## 현상

구현과 CLAUDE.md는 N=16/53건으로 바뀌었지만 이번 단계 지정 문서들은 이전 상태다.

- 펌웨어 설계서 §5.3의 1:1 의사코드는 N>16 분기 없이 `return n`하며 여러 절이 52건을 적는다.
- Frame 구조 명세서 §4는 N=0만 설명하고 N=16 상한을 누락했으며 §7은 52건이라고 적는다.
- SIAP 명세서 §9는 52건·경계 10건, §11은 52건 확장을 미래 작업으로 둔다.
- 개발 착수 지시서의 단계 2b 출구와 후속 C↔Python 대조도 52건으로 적는다.

그 상태에서 `firmware_verify.py 50/50`, `dev_verify.py 76/76`, `meta_verify.py 88/88`이 모두 통과했다.

## 영향

문서 의사코드를 옮기면 F-120이 재발하고, 단계 2b 출구가 53번째 B11을 요구하지 않는 것으로 읽힌다. 줄 단위 대응이라는 판정 기준 자체가 문서와 구현 사이에서 갈린다.

## 재현

```text
Python element_count(REQ_SET_DEVICE_CONTROL,119) -> None
C siap_element_count(...,119)                    -> -1
펌웨어 설계서 §5.3 의사코드                      -> 17
test_golden 실제                                 -> 53건/253검사
지정 문서 표기                                   -> 52건
```

## 제안

표준은 N 상한을 정하지 않으므로 프로젝트 결정 N=16이 옳다. 지정 문서의 N 산출과 모든 현재 벡터 수치를 구현에 맞추고 검증기가 문서 전수를 대조해야 한다.
