# F-057 · 테이블별 쓰기 소유권 표에서 실제 테이블 9개가 빠짐

| 항목 | 값 |

| 대상 | `project_docs/arch/아키텍처_설계서.md:283-325`, `project_docs/db/schema.sql` |

| 상태 | 수정완료 |

## 근거

1369-P1 7.2.2.2·7.2.2.6은 농장정보와 사용자정보를 데이터 생명주기 동안 관리하는 설정형 데이터로 정의한다. 7.2.2.8·7.2.2.10은 온실관리·장치관리 관계를, 7.2.3.4는 장치상태와 환경상태 사이의 작동환경 관계를 각각 정의한다.

아키텍처 §4.4는 쓰기 주체를 **테이블별 단일 소유자**로 확정하고, 같은 행을 두 스레드가 고치지 않게 하는 것이 이유라고 명시한다.

## 현상

`schema.sql`에는 31개 테이블이 있지만 §4.4-a의 소유권 표가 이름 또는 와일드카드로 포괄하지 못하는 테이블이 9개다.

```text
farm_info, greenhouse_info, user_info,
greenhouse_own, greenhouse_manage, device_manage,
operating_env, config_change_log, control_model
```

이 중 초기 시드로만 쓰일 수 있는 설정형 테이블, I/O 수신으로 생성될 수 있는 `operating_env`, MMS/API가 다룰 수 있는 `control_model`은 예상 소유자가 서로 다르므로 하나의 암묵 규칙으로 보완할 수도 없다.

## 영향

F-053의 수정 목표였던 DB 쓰기 주체 계약이 전체 스키마에 대해 닫히지 않았다. 구현자가 누락 테이블의 쓰기를 메인/API/I/O 중 어디에 배치할지 문서만으로 결정할 수 없고, "테이블별 단일 소유자"라는 아키텍처 불변식도 검증할 수 없다.

## 제안

31개 테이블이 모두 정확히 한 소유권 분류에 들어가도록 표를 완결하고, 시작 전 시드 전용 테이블은 런타임 쓰기 금지 여부까지 구분한다.
