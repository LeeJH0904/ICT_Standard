# F-218 · replay가 tx 기대 출력을 대조하지 않고 버림

| 항목 | 값 |
|---|---|
| 심각도 | 오류 |
| 분류 | 코드버그 |
| 대상 | `project_code/sim/replayer.py:38` · `project_code/run.py:313` · 아키텍처 설계서 §5.4-a |
| 발견일 | 2026-08-12 |
| 상태 | 신규 |

## 근거

공고문 「소스코드 제출 안내」 재현성 — “제출물만으로 실제 실행(재현)이 가능한 전체 소스코드”를 요구한다. 아키텍처 설계서 §5.4-a는 `dir=tx`를 “기대 출력으로 쓴다. 종단 테스트가 현재 게이트웨이의 송신과 대조한다”고 정하고, 그 대조가 “재현성의 정의”라고 명시한다.

## 현상

`Replayer._load_rx()`는 tx 레코드를 `skipped_tx`로 세고 바이트는 버린다. 현재 게이트웨이가 같은 요청에 무엇을 송신했는지와 비교하는 구현이 없다. `sim/tests/test_replayer.py`와 `mode_verify.py`도 tx가 주입되지 않았다는 사실만 검사한다.

유효한 `REQ_SET_CONNECTION` rx 뒤에 기대 tx를 `DEADBEEF`로 넣은 임시 로그를 실제 `run.py --mode replay`로 재생했다. 게이트웨이의 실제 응답과 명백히 다른 기대값인데도 “tx 레코드 1건은 기대 출력이므로 주입 제외”만 출력하고 종료 코드 0이었다.

## 영향

replay는 입력 재주입만 할 뿐 기록 세션의 양방향 동작을 재현했는지 증명하지 못한다. 설계서가 약속한 종단 대조가 없으므로 게이트웨이 응답 바이트가 회귀해도 기본 재현 경로가 성공한다.

## 재현

```jsonl
{t: 0.0, dir: rx, hex: 120000000100000000100003}
{t: 0.1, dir: tx, hex: DEADBEEF}
```

```text
python project_code/run.py --mode replay --log <위 임시 로그> --db <임시 DB> --speed 100
실측: 재생 1건, tx 레코드 1건 주입 제외, rx=1 tx=1 위반=0, exit 0
```
