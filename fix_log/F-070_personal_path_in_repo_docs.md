# F-070 · 저장소 문서에 개인 경로가 남아 있음 (블라인드 심사 위반)

| 대상 | `CLAUDE.md` §9 (표준 원문 경로), `진행보고서.md` 진행 현황 요약 |
| 발견일 | 2026-08-05 |
| 상태 | 수정완료 |

## 근거

`CLAUDE.md` §1-4 — **개인 식별정보** (`@author`, 이름, 학교, 소속, 연락처, 호스트명, **개인 경로**) 금지. 사유는 "블라인드 심사 위반".

공고문의 블라인드 심사 조항이 상위 근거이며, 위 규약은 그것을 프로젝트 규칙으로 옮긴 것이다.

## 현상

`CLAUDE.md` §9 참조 문서 절 말미에 표준 원문 위치가 사용자 홈 디렉터리를 포함한 절대 경로로 적혀 있다. 경로 문자열에 개인 식별 가능한 사용자명이 들어간다.

`진행보고서.md`의 "개발 방식" 문장에도 같은 형태의 경로가 있다.

## 영향

제출 zip 에 `CLAUDE.md` 가 포함되면 심사자가 제출자를 식별할 단서가 된다. 규약 §1이 스스로 "제출 실격·감점 사유"로 분류한 항목이다.

## 탐지가 늦은 이유

`fix_log/meta_verify.py` §5-a 의 비밀정보·개인식별 스캔은 다음 조건이었다.

```python
if q.suffix != ".md" and SECRET.search(line) and not allowed(q.name, line):
```

- `.md` 를 스캔 대상에서 제외한다 — 문서는 패턴을 인용할 수 있다는 이유였다.
- `SECRET` 정규식이 `api[_-]?key|password|passwd|secret|@author` 뿐이라 **경로 형태를 아예 보지 않는다.**

즉 이 항목은 두 조건 어느 쪽으로도 걸리지 않았다. 규약에 적혀 있으나 기계가 검사하지 않던 유일한 §1 항목이다.

`project_docs/firmware/firmware_verify.py` 는 설계서에 대해 `[A-Za-z]:\\Users\\|/home/[a-z]+/|/Users/[a-z]+/` 패턴을 검사하며, 이 검사가 확장 가능한 형태로 이미 존재한다.

## 제안

제출 패키징 시점에 다음을 한 번에 처리한다.

1. `CLAUDE.md` §9 · `진행보고서.md` 의 절대 경로를 자리표시자(`<표준 원문 경로>`)로 치환한다.
2. `meta_verify.py` 의 스캔을 확장한다 — `.md` 를 포함하고 `PRIVATE` 정규식(개인 경로)을 추가한다. `fix_log/` 는 계속 제외한다(결함 기록은 패턴을 인용한다).
3. 확장 후 전 파일 재스캔해 누락을 확인한다.
