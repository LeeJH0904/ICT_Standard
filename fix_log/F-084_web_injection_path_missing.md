## 근거

화면 설계서 §5.3은 버튼이 `sim/inject.py`에 골든 벡터 ID를 요청한다고 선언한다. 시연 시나리오는 영상에서 버튼을 클릭하고, 2차 시연에서는 심사위원이 8종 중 임의 입력을 선택하게 한다. 이는 핵심 기능 2와 표준활용성 30점의 직접 증거다.

## 현상

브라우저는 로컬 Python 모듈을 직접 호출할 수 없다. 그런데 화면↔API 대응표에서 `verify.html`의 쓰기 오퍼레이션은 0개이고, 21개 OpenAPI 오퍼레이션에도 주입·시뮬레이터 제어 경로가 없다. 파일·표준입력·WebSocket 등 다른 IPC 계약도 정의되지 않았다.

## 영향

설계대로 구현하면 주입 버튼은 실행할 대상이 없다. 외부 터미널에서만 `inject.py`를 실행하면 영상의 “버튼 클릭”과 발표의 “심사위원 임의 선택”을 재현할 수 없어 핵심 기능 2의 사용자 흐름이 붕괴한다.

## 제안

`simulate`/`replay` 모드에서만 허용되는 명시적 주입 API 또는 로컬 IPC를 정의하고, 하드웨어 모드·일반 운영에서는 차단한다. 읽기 전용 화면이라는 선언도 “운영 상태 변경 없음”처럼 주입과 모순되지 않는 표현으로 조정한다.
