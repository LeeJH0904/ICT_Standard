# F-107 · Frame 구조 명세서가 단계 1 구현과 동기화되지 않음

## 근거

단계 1 대조 기준인 Frame 구조 명세서는 계약 경계와 `FrameBuilder` 목록 및 검증 결과를 정의한다. 표준 원문 TTAK.KO-10.0943 표 7-2는 `REQ_SET_DEVICE_PROPERTY` 0x0004를 양방향으로 허용하고, §8.1.3.2는 기본 Request 방향을 GCG→노드로 정하며 온실통합제어기가 N개 디바이스 속성값을 보내는 메시지라고 명시한다.

따라서 게이트웨이발 `set_device_property` 빌더를 가진 현재 구현이 표준 원문에 맞고, 이를 빠뜨린 설계 문서가 틀렸다.

## 현상

- 문서 머리말과 §6은 계약 검증을 53/53으로 기술하지만 실제 `test_contract.py`는 56/56이다.
- §5.1의 게이트웨이발 Request 목록은 `set_device_property`를 누락한다. 실제 `siap_iface.py`에는 해당 메서드가 있고 테스트도 F-086 계약으로 확인한다.
- §7은 이미 신설·이관된 `fake_link.py`와 `vectors/golden.jsonl`을 여전히 다음 단계 산출물로 적는다.

`dev_verify.py` 76/76, `test_contract.py` 56/56, `layer_verify.py` 7/7 및 전체 `run_all.py` 11/11은 이 현재 서술 드리프트를 모두 통과했다.

## 영향

단계 2 구현자가 정본 설계의 불완전한 builder 목록을 따르면 표준이 요구하고 API·화면이 사용하는 디바이스 속성 설정 송신 경로를 다시 누락할 수 있다. 검증 수치와 다음 단계 목록도 현재 완료 상태를 잘못 표시한다.

## 재현

1. `python project_code/contracts/test_contract.py`를 실행해 56/56을 확인한다.
2. `siap_iface.py`의 `set_device_property` 및 대응 테스트를 확인한다.
3. Frame 구조 명세서 §5.1·§6·§7의 목록과 비교한다.
4. 0943 원문 표 7-2와 §8.1.3.2의 방향·페이로드 설명으로 구현과 문서 중 어느 쪽이 맞는지 판정한다.

## 제안

§5.1에 `set_device_property`를 추가하고 §6 수치·항목을 56종 실측과 동기화한다. §7에서 완료된 단계 1 산출물을 제거하거나 완료 표시로 분리하며, 검증기가 현재 수치와 산출물 상태를 대조하도록 한다.
