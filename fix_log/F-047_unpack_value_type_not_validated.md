## 근거

0943 표 7-14 — `Value Type`: INT `0x00`, UNSIGNED INT `0x01`, FLOAT `0x02`, RESERVED `0x03`

0943 표 7-10 — `INVALID_DATA_TYPE (0x06)`: "데이터 타입 오류"

## 현상

`pack_value()`는 0x03과 미정의 타입을 거부하지만 `unpack_value()`는 FLOAT와 INT만 분기하고 나머지를 모두 그대로 반환한다. 따라서 0x03뿐 아니라 0x04, 0x63 같은 2비트 밖의 잘못된 호출값도 UINT처럼 해석된다. 새 15종 테스트의 “Reserved 차단”은 인코딩 경로만 검사해 디코딩 공백을 잡지 못한다.

## 영향

명세 검증기의 왕복 디코더가 표준상 데이터 타입 오류인 바이트를 정상 정수값으로 인정한다. 이를 실제 디코더의 기준으로 옮기면 기능 2가 `INVALID_DATA_TYPE` 위반을 놓친다.

## 재현

```python
unpack_value(BitReader(b"\x00\x00\x00\x01"), 3)   # 1 반환
unpack_value(BitReader(b"\x00\x00\x00\x01"), 99)  # 1 반환
```

## 제안

디코딩도 `vtype in (0, 1, 2)`를 강제하고 0x03 및 미정의값을 실패시킨다. 인코딩·디코딩 양쪽의 Reserved 회귀 테스트를 분리한다.
