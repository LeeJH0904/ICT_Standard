# F-101 · 기본 회귀가 spec_examples 드리프트를 덮어써 F-063 재발을 마스킹

## 근거

`CLAUDE.md` §6.2 — 골든 산출물을 검증 중 덮어쓰면 드리프트를 마스킹하며, 검증기는 독립 입력과 대조해야 한다.

F-063 처리 기록은 생성기 2종에 `--check`를 넣어 검증 중 산출물 덮어쓰기를 막았다고 판정했다.

## 현상

`spec_verify.py`는 `--check`가 있을 때만 현재 `spec_examples.json`과 생성 결과를 대조한다. 인자가 없으면 345행에서 대상 파일을 먼저 덮어쓰고 성공한다.

`run_all.py`는 발견한 모든 검증기를 추가 인자 없이 실행한다. 따라서 전체 회귀의 `spec_verify.py`는 F-063의 비변경 검사 경로가 아니라 생성 경로로 실행된다.

임시 복제본에서 `spec_examples.json`을 손상한 실제 결과는 다음과 같다.

- 손상 직후 `spec_verify.py --check`: 종료 1
- `run_all.py`와 같은 기본 `spec_verify.py`: 종료 0
- 기본 실행 뒤 `spec_verify.py --check`: 종료 0

기본 검증이 손상 증거를 지운 뒤 통과시켰다. F-063의 수정완료 상태가 전체 회귀 경로에서는 성립하지 않는다.

## 영향

체크인된 예시 프레임이 생성 정본과 달라도 `run_all.py` 10/10이 될 수 있다. 검증 과정이 `fix_log/` 밖 파일도 변경하므로 독립 검증의 비변경 원칙도 깨진다.

## 재현

1. 임시 복제본의 `project_docs/siap/spec_examples.json`을 임의 문자열로 바꾼다.
2. `python spec_verify.py --check`가 종료 1인지 확인한다.
3. `python spec_verify.py`를 실행하면 종료 0이다.
4. 다시 `--check`를 실행하면 종료 0이다.

## 제안

검증기 기본 동작을 비변경 대조로 두고 생성은 명시적인 별도 인자로만 허용한다. 또는 `run_all.py`가 이 검증기에 `--check`를 전달하되 검증기 목록을 하드코딩하지 않는 일반 메타데이터 방식으로 처리한다.
