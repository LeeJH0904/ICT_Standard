## 근거

공고문 「소스코드 제출 안내」 진위·창작성 — “제출한 소스코드는 증빙영상·발표 시연의 구현 내용과 일치해야 하며, 빈 코드·무관한 코드·표절 등 명백한 허위일 경우 심사에서 제외함.” CLAUDE.md §1-1 — “하드코딩된 가짜 센서값을 로그·데모에 사용” 금지. 현재 GPT 검증 프롬프트 단계 4 추가 지시 — “`logs/` 에 합성 데이터(random·math.sin·하드코딩 센서값)가 있는가 → 실격 사유다.”

## 현상

F-148을 기각하면서 CLAUDE.md §7과 아키텍처 §5.5에 단계 4~7 예외를 새로 적었지만, 이번 독립 검증의 직접 판정 기준과 저장소의 GPT 검증 프롬프트는 예외 없이 `logs/`의 하드코딩 센서값을 실격 사유로 둔다. CLAUDE.md §1-1의 절대 금지 행도 그대로다. 반면 `project_code/logs/session_00_golden.jsonl:3`은 여전히 `0x41CA6666`(약 25.3)과 `0x42740000`(61.0)을 센서 관측값으로 담고 기본 replay가 이를 재생한다.

개발 착수 지시서 §3.6의 “그전까지는 골든 벡터만 재생”은 중간 개발 경로를 설명하지만, 이번 검증에 명시된 “하드코딩 센서값이 logs에 있으면 실격” 기준을 폐기하지 않는다. F-148 기각은 코드 변경 없이 더 낮은 문서에 예외를 추가해 상충하는 판정 기준을 만든 것이므로 사유가 불충분하다.

## 영향

같은 제출물을 CLAUDE.md §7은 허용하고 CLAUDE.md §1-1·GPT 검증 프롬프트·이번 독립 검증 지시는 실격으로 판정한다. 독립 검증자는 현 기준에서 치명 요건위반 판정을 철회할 수 없고, 기본 replay 로그의 진위 위험도 그대로 남는다.

## 제안

사용자가 단계 4~7 예외가 기존 독립 검증 지시를 명시적으로 대체한다고 확정하거나, 평가 대상 `logs/`에서 하드코딩 센서값을 제거해야 한다. 문서 일부만 예외로 바꾸어서는 기각 근거가 닫히지 않는다.
