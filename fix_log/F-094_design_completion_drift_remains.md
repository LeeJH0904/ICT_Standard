## 근거

F-087은 A.1-5를 `⚠`로 낮추고 부속서 A 집계를 `✅16 / ⚠5 / ❌10`으로 확정했다. F-090은 설계 완료 시점의 API 쓰기 7건, DB 87종 등 현재 수치를 모든 문서에 동기화한 것으로 처리됐다.

## 현상

- 화면 설계서 §9는 A.1-5가 닫혔다고 적고 부속서 A를 `✅17 / ⚠4`로 계산한다. 실제 대조표는 A.1-5가 `⚠`, 집계는 `✅16 / ⚠5 / ❌10`이다.
- 0937 대조표 §5는 다시 A.1-5가 사라졌다고 적고, `⚠ 7건`, API 쓰기 4건, DB 제약 테스트 76종, 쓰기 4→5를 현재 전제로 남긴다. 같은 문서의 실제 집계는 `⚠ 6건`, 현재 검증은 DB 87종, OpenAPI 쓰기는 7건이다.
- 0937 대조표 6.2-3과 5-2도 쓰기 4건·4→6을 전제로 한다.
- API 명세서 검증표는 쓰기 7건이라고 적은 바로 아래에서 “넷 다 mutation 태그”라고 적는다.

## 영향

요구사항 충족 범위와 변경 영향도를 읽는 사람에게 서로 다른 정답을 준다. 특히 A.1-5의 과대 판정은 F-087을 다시 되돌리고, 후속 API 추가 시 쓰기 표면 계산도 잘못 출발한다.

## 제안

F-087 확정 집계와 현재 실측(쓰기 7, DB 87)을 정본으로 전수 치환하되 역사적 전이 수치는 “당시 4→5, 이후 거부·주입 추가로 현재 7”처럼 시점을 명시한다. 후속 과제의 예상 증가도 현재 7에서 다시 계산한다.
