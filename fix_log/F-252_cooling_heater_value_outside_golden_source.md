# F-252 · 냉난방기 초기값이 골든 원본 밖의 하드코딩 값으로 회귀

## 근거

`CLAUDE.md` §1-1은 하드코딩된 가짜 센서값의 로그·데모 사용을 금지하며, 단계 4~7 예외도 감사된 `golden.jsonl` 원본 값의 재사용으로 한정한다. 개발 착수 지시서 §3.6도 “그전까지는 골든 벡터만 재생한다”고 정한다.

선행 결함 F-216은 가상 노드의 실제 `(Subtype, Value Type, Value)` 전량을 정상 골든 벡터의 집합과 독립 대조하도록 고쳐 `수정완료`되었다.

## 현상

F-241 이후 추가된 냉난방기 장치는 `SUBTYPE_COOLING_HEATER = 0x86`에 대해 값 풀에 해당 subtype이 없으면 `(wire.VT_INT, 20)`을 fallback으로 사용한다. 현재 `golden.jsonl` 정상 벡터에는 `(134, 0, 20)`이 존재하지 않는다.

도구를 저장소 루트 구조로 복원해 제출 소스를 대상으로 `mode_verify.py`를 실행하면 F-216 회귀 검사가 다음과 같이 실패한다.

```text
FAIL simulate 초기 장치값이 golden.jsonl 정상 벡터 원본에 전량 존재 (F-216)
     골든 밖 값=[(134, 0, 20)]
11/12 통과
```

개발용 `project_code`와 최종 제출본 모두 같은 값을 사용한다.

## 영향

시뮬레이션 화면·장치상태에 나타나는 초기 목표온도 20의 출처를 골든 원본이나 실측 로그로 증명할 수 없다. “시뮬레이션 장치값도 감사된 골든 원본 그대로”라는 데이터 진위 계약과 F-216의 수정완료 상태가 동시에 깨진다.

## 재현

```powershell
# tools/가 저장소 루트에 있는 정상 구조에서
python .\tools\mode_verify.py
# 11/12, 골든 밖 값=[(134, 0, 20)], exit 1

rg -n "SUBTYPE_COOLING_HEATER|VT_INT, 20" .\project_code\sim\virtual_node.py
```

## 제안

냉난방기 subtype의 정상 원본 벡터를 독립 근거와 함께 골든 정본·양쪽 사본에 추가하고 교차 검증을 갱신하거나, 이미 존재하는 정상 골든 subtype/value만 데모 장치에 사용한다. fallback이 골든 밖 값을 만들면 즉시 실패하도록 가상 노드 생성 자체에도 방어를 두는 편이 안전하다.
