# F-148 · 기본 replay·simulate가 고정 센서값을 데모 데이터로 사용

| 항목 | 값 |

## 근거

공고문 「소스코드 제출 안내」 진위·창작성 — “제출한 소스코드는 증빙영상·발표 시연의 구현 내용과 일치해야 하며, 빈 코드·무관한 코드·표절 등 명백한 허위일 경우 심사에서 제외함.” CLAUDE.md §1-1은 이를 이 프로젝트에서 하드코딩된 가짜 센서값을 로그·데모에 사용하는 행위의 금지로 구체화한다. 개발 착수 지시서 §3.6도 합성 데이터를 하지 말라고 명시한다. 아키텍처 설계서 §5.5는 센서값에 실측 로그의 값 분포를 재사용하라고 정한다.

## 현상

기본 `logs/session_00_golden.jsonl` 3행은 골든 N34의 `Value` 비트패턴 `0x41CA6666`(FLOAT 약 25.3)과 `0x42740000`(FLOAT 61.0)을 센서 프레임으로 담는다. `run.py --mode replay`는 이 파일을 기본 입력으로 재생한다. `virtual_node.py`도 같은 골든 파일에서 값 풀을 만들고 simulate의 주기 센서 알림에 사용한다.

이는 테스트 벡터를 검증 데이터로 쓰는 데서 끝나지 않고 `logs/`와 기본 데모의 센서 관측값으로 제시하는 것이다. 코드 주석의 골든이므로 합성이 아니라는 자체 예외는 CLAUDE.md §1-1과 아키텍처 §5.5에 근거가 없다. 설계서의 실측값 요구가 프로젝트 규약과 일치하므로 설계가 옳고 구현이 틀렸다.

## 영향

사용자 추가 지시가 명시한 실격 항목이다. 기본 replay와 simulate가 모두 고정 센서값을 화면·로그에 노출하므로 제출·영상의 진위를 공격받을 수 있다.
