## 근거

`fix_log/README.md` §1 — “모든 발견은 `bug_fix_list.md`에 한 줄이 있어야 하며, 인덱스에 없는 개별 파일은 존재해서는 안 된다.”

`fix_log/README.md` §9 — GPT는 인덱스에 행을 추가하고 상세 파일을 만들며, 상태 전이는 인덱스에 남아야 한다.

## 현상

`F-187_frame_fields_payload_incomplete.md`와 `F-188_run_py_uvicorn_not_wired.md`가 존재하지만 `bug_fix_list.md`에는 두 ID의 행이 없다. 따라서 현황 합계, 보류 건수, 최대 ID가 실제 상세 기록과 다르다.

`meta_verify.py`는 인덱스 행마다 대응 상세 파일이 있는지만 순회한다. 반대 방향인 “모든 `F-###_*.md`가 인덱스에 있는가”는 검사하지 않는다. 그 결과 다음과 같이 거짓 통과했다.

```text
PASS 인덱스 행 파싱 (182건)
PASS '다음 ID'가 최대 ID보다 큼 (다음=189, 최대=186)
PASS 상세 파일 누락 없음
102/102 통과
```

## 영향

F-187·F-188은 검증 대기 목록과 현황 표에서 보이지 않는다. 단계 7 착수 전 처리해야 한다는 보류 기록도 인덱스 기반 워크플로에서 유실된다.

## 재현

```powershell
rg --files fix_log | rg "F-18[78]_"
rg -n "^\| F-18[78] " fix_log/bug_fix_list.md
python fix_log/meta_verify.py
```

첫 명령은 상세 파일 2개를 출력하고, 두 번째 명령은 0건이며, 세 번째 명령은 102/102로 통과한다.
