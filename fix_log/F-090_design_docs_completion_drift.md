## 근거

진행보고서 첫머리는 새 단계가 끝날 때마다 절을 추가한다고 선언하며, GPT 역할 지시서는 이 문서를 전체 진행 동향의 시작점으로 지정한다. 각 설계서는 대응 기계 산출물과 수치가 일치해야 한다.

## 현상

현재 실제 값은 OpenAPI **경로 20개·오퍼레이션 21개·쓰기 5개**, API 검증 **40/40**, 표준결함 **19건**이다. 그러나 다음 이전 값이 남아 있다.

- `API_명세서.md`: operationId 20건, 쓰기 4건, 검증 35/35, mutation 태그가 mms/fcs뿐이라고 기록.
- 아키텍처 §4.4-a와 0937 대조표 §5: 새 설정 경로를 반영한 대목과 “쓰기 4건” 서술이 공존.
- `진행보고서.md`: 최종 갱신 8월 3일, 표준결함 18건, API 20종·35/35, 펌웨어·시연을 이후 예정으로 기록하며 0937 대조·펌웨어·시연·화면 설계 완료를 요약·문서 지도에 반영하지 않음.
- 화면 설계서: 경로 수를 오퍼레이션 수와 혼동해 “경로 21종”으로 기록.

## 영향

설계 문서를 모두 마쳤다는 현재 상태와 프로젝트의 첫 안내 문서가 반대 내용을 말한다. 구현자가 API 명세서의 쓰기 4건을 정본으로 따르면 새 설정 API를 누락하고, 심사 자료 수치도 문서마다 달라진다.

## 제안

완료 시점의 단일 수치표를 재산출해 진행보고서·API 명세서·아키텍처·0937 대조표·화면 설계서에 동기화하고, 메타 검증에 단계 목록과 API 경로/오퍼레이션/쓰기/검증 건수 교차 검사를 추가한다.
