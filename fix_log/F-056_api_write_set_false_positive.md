# F-056 · API 검증기가 쓰기 경로 교체를 거짓 통과시킴

| 항목 | 값 |

| 상태 | 수정완료 |

## 근거

0937 6.3은 모델관리서비스, 6.5는 스마트팜제어서비스의 역할을 각각 구분한다. API 명세서 §3도 쓰기 계약을 `POST /rules`, `/approve`, `/execute`, `/control`의 정확한 4경로로 확정했다.

## 현상

검증 항목 이름은 "쓰기 오퍼레이션이 제어·승인 경로 4건뿐"이라고 하지만 판정식은 `len(writes) == 4`뿐이다. 경로 집합을 비교하지 않으며, 출력 문구도 F-053에서 폐기한 "API 스레드 읽기 전용 원칙"을 아직 사용한다.

`POST /rules`를 제거하고 같은 요청·응답을 뜻하지 않는 `POST /health`로 옮긴 변형 OpenAPI를 메모리에서 주입해 실행했더니, 출력 목록에 `/health`가 보이는데도 전체 **34/34, 종료코드 0**으로 통과했다.

## 영향

필수 쓰기 경로 하나가 사라지고 금지하지 않은 mutation 경로가 생겨도 검증기가 성공한다. F-053으로 재정의한 API 쓰기 표면을 회귀 테스트가 실제로 보호하지 못한다.

## 재현

```text
1. openapi.json 사본에서 POST /api/v1/rules를 제거한다.
2. 같은 operation을 POST /api/v1/health로 옮기고 operationId만 고유하게 바꾼다.
3. api_verify.py를 실행한다.
4. "POST /api/v1/health"가 목록에 있는데도 34/34, exit 0이다.
```

## 제안

개수가 아니라 허용된 `(method, path)`의 정확한 집합을 대조하고, 검증 이름을 현재의 테이블별 쓰기 소유권 원칙에 맞춘다.
