# 시연 시나리오 설계서

> **대상**: ① 1차 서면평가 제출 영상(2분) ② 2차 발표평가 현장 라이브 시연
> **입력**: 공고문 제출물 규격·평가기준, `project_docs/` 설계 문서 6종, `contracts/vectors/golden.jsonl`
> **검증**: `project_docs/demo/demo_verify.py` — 컷 시간·평가항목 커버리지·위반 케이스를 기계 대조한다
> **전제**: 실물 3종(Uno · Pro Mini · ESP32) 확보 완료. 영상 배분은 **기능 2(표준 준수 검증) 중심**

---

## 0. 이 문서가 결정하는 것

| 결정 | 값 | 근거 |
|---|---|---|
| 영상 총 길이 | **117초** (여유 3초) | §3 |
| 기능 2 배분 | **53초 (45%)** | 배점 최대 항목(표준활용성 30점) |
| 실물 등장 | **S2 · S3 두 컷** | 3종 혼용 주장의 시각 근거 |
| 촬영 순서 | **편집 순서와 다르다** — 로그 일관성이 우선 | §4 |
| 제출 로그 | **촬영 세션에서 캡처한 것을 그대로 제출** | §4.3 |
| 발표 시연 폴백 | **4단계** (실물 → simulate → replay → 녹화) | §7.4 |

**두 시연은 다른 물건이다.** 영상은 편집으로 실패를 지울 수 있고 2분에 갇힌다. 발표 시연은 라이브고
질의응답이 붙는다. 같은 기능을 보여주지만 **순서·길이·실패 대응이 전부 다르다.**

## 1. 제출 규격 (공고문)

| 항목 | 요구 | 본 계획 |
|---|---|---|
| 형식 | mp4 등 **1개 파일** | mp4 (H.264) |
| 길이 | **2분 이내** | 117초 |
| 해상도 | **FULL HD 이상** | 1920×1080 / 30fps |
| 용량 | 500MB 이하 권장 | 목표 80MB 이하 |
| 블라인드 | 성명·소속·학교·로고·**얼굴** 노출 금지. **화면 시연 위주** | §5 |
| 진위·창작성 | 소스코드와 **일치**. 빈 코드·무관한 코드는 심사 제외 | §4.3 |

> **"화면 시연 위주"가 실물 촬영을 금지하지는 않는다.** 금지 대상은 응모자를 특정할 수 있는 정보다.
> 보드를 검은 배경지 위에서 근접 촬영하면 요건을 만족하면서 3종 혼용을 시각적으로 증명할 수 있다.
> 손이 화면에 들어가지 않게 하고(장갑도 피한다 — 오히려 눈에 띈다), 반사면에 얼굴이 비치지 않게 한다.

## 2. 영상이 증명해야 하는 것 — 배점과 컷의 대응

1차 평가 5개 항목(105점)에 각 컷을 대응시킨다. **어느 항목도 담당 컷이 없으면 안 된다.**

| 평가항목 | 배점 | 담당 컷 | 화면에서 무엇이 보이는가 |
|---|---|---|---|
| 표준 활용성 및 문제해결 연결성 | **30** | **S4** | 위반 프레임 판정 결과에 **표준 조항 번호가 그대로 출력**된다 |
| 개발의 참신성 | **25** | S1 · S2 | 표준 3건 조합. 같은 바이트열이 서로 다른 MCU·전송계층을 지난다 |
| 생성형 AI 활용성 | 15 | S5 | AI가 만든 규칙 초안이 **승인 없이는 구동기에 닿지 않는다** |
| 구현완성도·서비스 가능성 | 15 | S3 · S5 | 노드 등록 → 실시간 값 → 제어 왕복의 사용자 흐름 |
| 공공편익·포용성 | 15 | S1 · S6 | 벤더 종속 해소. 하드웨어 없이 누구나 재현 |
| (가산) 공공데이터 | 5 | S5 | 기상청 예보가 규칙 생성 입력으로 들어간다 |

**S6(재현성)은 배점표에 직접 대응하는 항목이 없지만 뺄 수 없다.** 공고문이 *"제출물만으로 실제
실행(재현)이 가능"* 을 **필수**로 걸고 *"재현 불가 시 서면 평가에서 제외"* 라고 적었다. 배점 이전의 통과 조건이다.

## 3. 영상 컷 구성 — 117초

| # | 시작 | 길이 | 화면 | 자막 | 담당 항목 |
|---|---|---|---|---|---|
| S1 | 0:00 | 8s | 검은 화면에 표준 3건 번호가 순차 등장 → 한 줄 요약 | "TTA 표준 3건의 참조 구현과 상호운용성 검증 도구" | 참신성 · 공공편익 |
| S2 | 0:08 | 14s | 보드 3종 근접 → 분할 화면으로 `core/` 파일 SHA-256 3열 일치 | "동일한 응용계층 코드. 전송 계층만 다르다" | 참신성 |
| S3 | 0:22 | 18s | 기능 1 대시보드. 노드 3대 등록 → 센서값 실시간 갱신 | "8.1.1 연결 설정 · 표 7-13 노드 속성" | 구현완성도 |
| **S4** | **0:40** | **53s** | **기능 2 표준 준수 검증** (§3.1 세부) | (세부 참조) | **표준 활용성** |
| S5 | 1:33 | 20s | 기능 3. 기상청 예보 → AI 규칙 초안 → **승인 게이트** → 구동기 동작 | "승인 전에는 구동기에 도달하지 않는다" | AI활용성 · 구현완성도 |
| S6 | 1:53 | 20s | 터미널에서 검증기 8종 + 호스트 유닛테스트 연속 통과 | "하드웨어 없이 표준 준수를 검증한다" | 재현성 |
| S7 | 2:13 | 4s | 표준↔코드 매핑 요약 카드 | 3건 · 조항 수 · 검증 건수 | — |

> 합계 **137초 → 2분 초과**다. S3·S5·S6 을 각각 4·3·8초 줄여 **117초**로 맞춘다. 아래 §3.2 가 확정판이다.

### 3.1 S4 세부 — 기능 2 (53초)

이 컷이 배점 최대 항목을 혼자 담당한다. **조항 번호가 화면에 보이는 시간이 곧 점수다.**

| 구간 | 길이 | 내용 |
|---|---|---|
| S4-a | 8s | 정상 프레임 수신 → hex 원문과 필드 분해가 나란히 표시. `Message Type`(14bit)이 바이트 경계를 넘는 지점을 강조 |
| S4-b | 30s | **위반 프레임 주입 5종을 순차 실행.** 각 6초 — 주입 버튼 클릭 → 판정 결과에 `코드명(0x??) — N절` 출력 |
| S4-c | 9s | 나머지 3종을 3초 몽타주로 빠르게 흘림 + 8종 판정표 전체를 한 화면에 |
| S4-d | 6s | `NEC` 알림을 **위반이 아니라 alert 으로 분리 처리**하는 장면 |

**S4-b 에서 보여줄 5종** — 골든 벡터 `X01`~`X08` 중 화면에서 가장 명확한 것을 고른다.

| 순서 | 골든 | 주입 | 화면 출력 | 조항 |
|---|---|---|---|---|
| 1 | `X01` | `Version` 을 0x99 로 조작 | `INVALID_VERSION (0x01) — 7.3.1절` | 7.3.1 |
| 2 | `X03` | `Payload Length` 를 실제와 다르게 | `INVALID_FORMAT (0x09) — 7.3.1절` | 7.3.1 |
| 3 | `X05` | `Transmission Type` = 0x03 | `INVALID_TRANSMISSION_TYPE (0x08) — 표 7-6` | 표 7-6 |
| 4 | `X06` | `Value Type` = 0x03 (Reserved) | `INVALID_DATA_TYPE (0x06) — 표 7-14` | 표 7-14 |
| 5 | `X07` | 미등록 `Subtype` | `INVALID_DATA_SUBTYPE (0x07) — 표 7-14` | 표 7-14 |

**S4-c 몽타주 3종**: `X02`(미등록 Node ID) · `X04`(Reserved Message Type) · `X08`(NEC 배터리 저전력).

> **주입은 실제 바이트를 바꾼다.** 화면에 결과만 찍는 것이 아니라 `sim/inject.py` 가 골든 벡터의
> hex 를 그대로 링크에 흘려보낸다. **영상 속 hex 와 제출 `golden.jsonl` 의 hex 가 같아야 한다** —
> 심사자가 대조할 수 있어야 "진위·창작성" 조항을 통과한다.

### 3.2 확정 컷 시트 — 117초

| # | 시작 | 길이 | 화면 |
|---|---|---|---|
| S1 | 0:00 | 8s | 표준 3건 타이틀 |
| S2 | 0:08 | 14s | 보드 3종 + `core/` 해시 일치 |
| S3 | 0:22 | 14s | 기능 1 대시보드 — 3노드 등록·실시간 값 |
| S4 | 0:36 | 53s | 기능 2 표준 준수 검증 (§3.1) |
| S5 | 1:29 | 17s | 기능 3 — 예보 → AI 초안 → 승인 게이트 → 구동 |
| S6 | 1:46 | 8s | 검증기 8종 + 호스트 테스트 통과 (배속) |
| S7 | 1:54 | 3s | 매핑 요약 카드 |
| — | **1:57** | **117s** | 여유 3초 |

**S6 를 8초로 줄이는 방법**: 8개 검증기를 하나의 스크립트로 연속 실행하고 **4배속**으로 흘린다.
마지막 `8/8 통과` 요약 줄만 실속으로 1.5초 정지. 개별 결과를 읽히려는 컷이 아니라
**"하드웨어 없이 돌아간다"는 사실 하나**를 보여주는 컷이다.

## 4. 촬영 순서 — 편집 순서와 다르다

### 4.1 왜 다른가

컷 번호대로 찍으면 **S3·S4·S5 가 서로 다른 세션이 되어 로그가 갈린다.** 제출하는
`logs/session_*.jsonl` 은 영상 촬영 세션에서 캡처한 것이어야 하므로(§4.3), 화면 시연 세 컷은
**한 번에 연속으로** 찍어야 한다.

### 4.2 순서

| 단계 | 작업 | 산출 |
|---|---|---|
| T1 | 블라인드 사전 점검 (§5) — 프롬프트·북마크·경로·스티커 | 점검표 |
| T2 | 하드웨어 세팅 촬영 (S2 전반) — 검은 배경지, 보드 3종 | 실물 클립 |
| T3 | **화면 시연 연속 녹화** — 기능 1 → 기능 2 → 기능 3 을 끊지 않고 | 원본 화면 클립 + **`logs/session_01.jsonl`** |
| T4 | 검증기 실행 녹화 (S6) | 터미널 클립 |
| T5 | `core/` 해시 대조 녹화 (S2 후반) | 터미널 클립 |
| T6 | 타이틀·요약 카드 제작 (S1 · S7) | 정지 화면 |
| T7 | 편집 — S1~S7 순서로 재배열, 자막 삽입 | mp4 |
| T8 | 블라인드 사후 점검 — 완성본을 프레임 단위로 확인 | 점검표 |

**T3 가 실패하면 T4~T8 이 무의미하다.** T3 를 먼저 리허설로 한 번 돌리고, 로그가 정상 캡처되는지
확인한 뒤 본 촬영에 들어간다.

### 4.3 촬영 세션 로그 = 영상↔코드 일치의 증거

```
촬영 세션 --spy://--> logs/session_01.jsonl  ──> 그대로 제출
                            │
                            └─> --mode replay 로 심사자 PC 에서 재생 가능
```

| 규칙 | 내용 |
|---|---|
| 캡처 방법 | `spy://` 트랜스포트가 송수신 바이트를 자동 기록. 별도 캡처 코드 없음 |
| 포맷 | `{"t": 0.000, "dir": "rx", "hex": "12000A..."}` |
| 합성 금지 | `random.*` · `math.sin` 로 만든 값은 **제출 실격 사유**(CLAUDE.md §1-1). 사인파 온도는 즉시 드러난다 |
| 의도적 포함 | 결측 프레임 · 형식 위반 · 응답 지연 · 배터리 저전력 알림 |
| 대조 가능성 | 영상 한 켠에 기능 2 프레임 콘솔을 노출 → 심사자가 제출 로그와 영상 속 hex 를 직접 대조 |

> **"의도적 포함"이 감점 요인이 아니라 득점 요인이다.** 2차 평가의 *"오류·환각 대응 및 사람 검토
> 지점이 설명되는가"*(30점 항목)에 대한 답이 이 로그다. 완벽하게 깨끗한 로그는 오히려
> 합성을 의심하게 만든다.

## 5. 블라인드 점검

공고문: *"평가 대상 제출물에는 응모자를 특정할 수 있는 정보(성명·소속·학교·로고·얼굴 등)를
표기·노출할 수 없음"*. 위반은 **감점이 아니라 평가 제외 사유**다.

### 5.1 화면 녹화

| 항목 | 위험 | 조치 |
|---|---|---|
| 터미널 프롬프트 | `user@name-laptop` | `PS1='$ '` 로 고정. Windows 는 `prompt $G` |
| 파일 경로 | `C:\Users\<이름>\...` | 프로젝트를 **`C:\demo`** 로 복사해 촬영 |
| 브라우저 | 북마크바 · 프로필 아이콘 · 확장 아이콘 | **시크릿 창** + 북마크바 숨김 + 전체화면(F11) |
| 창 제목 표시줄 | 사용자명 포함 경로 | 전체화면 또는 크롭 |
| 에디터 | 최근 파일 목록 · Git 사용자명 | 에디터는 아예 화면에 넣지 않는다 |
| 알림 팝업 | 메신저·메일 미리보기 | **방해 금지 모드** 필수 |
| 바탕화면 | 아이콘·배경사진 | 촬영 중 바탕화면 노출 금지 |

> **경로 문제는 `F-070` 과 같은 뿌리다.** 저장소 문서의 개인 경로는 제출 직전 일괄 정리하기로
> 보류했지만(F-070), **영상은 편집으로 되돌릴 수 없다.** 촬영 시점에 이미 `C:\demo` 여야 한다.

### 5.2 하드웨어 촬영

| 항목 | 조치 |
|---|---|
| 배경 | **검은 배경지.** 책상·벽지·방 구조가 나오지 않게 |
| 반사면 | 보드 금속면·아크릴에 얼굴·창문이 비치지 않게 조명 각도 조정 |
| 스티커 | 노트북·보드·케이스의 학교·이름 스티커 제거 |
| 손 | 프레임 안에 넣지 않는다. 조작이 필요하면 컷을 나눈다 |
| 주변 사물 | 학생증·명찰·택배 송장·달력 |

### 5.3 음성·자막

| 항목 | 조치 |
|---|---|
| 음성 | **내레이션 없이 자막만** 쓴다. 목소리는 특정 가능성이 있고 2분에 담을 정보량도 자막이 크다 |
| 배경음 | 라이선스가 명확한 무료 음원 또는 무음. 사용 시 기획서에 출처·라이선스 명기 (공고문 요구) |
| 자막 표기 | 팀명·제목에 학교·지역명 금지. "표준 참조 구현" 같은 중립 표현 |
| 파일명 | 팀명은 zip 파일명에만. 영상 파일명은 중립 (`demo.mp4`) |

| ESP32 Wi-Fi 미접속 | `sim/virtual_node.py` 로 3번째 노드 대체 | **자막에 명시한다.** 숨기면 "진위" 조항 위반 |
| 노드 1대 응답 없음 | 2종으로 축소 촬영 (실행계획 리스크 #2) | S2 자막을 "2종"으로 수정 |
| 센서 값이 튄다 | **그대로 둔다** | 오히려 실측 증거다. 완벽한 곡선이 의심을 산다 |
| 위반 주입이 판정되지 않음 | 촬영 중단. 코드 문제이므로 편집으로 덮지 않는다 | — |
| 프레임 유실로 재동기 발생 | 그대로 둔다 | 표준결함 #10(F-069)의 실증 장면이 된다 |
| 로그 캡처 실패 | **촬영 전체 재실시.** 로그 없는 영상은 대조 근거가 없다 | — |

> **편집으로 덮어도 되는 것과 안 되는 것을 나눠야 한다.** 화면 전환 · 대기 시간 단축 · 배속은
> 편집의 정상 범위다. **동작하지 않은 기능을 동작한 것처럼 보이게 하는 것**은 심사 제외 사유다.

## 7. 2차 발표평가 — 현장 라이브 시연

### 7.1 조건이 다르다

| 항목 | 영상 | 현장 |
|---|---|---|
| 편집 | 가능 | **불가** |
| 실패 | 재촬영 | 그 자리에서 대응 |
| 네트워크 | 통제됨 | **불확실. 없다고 가정한다** |
| 하드웨어 | 자기 책상 | 반입·결선 시간 제한 |
| 질의응답 | 없음 | **20점 항목** |

2차 배점 100점 중 **SW 개발 완성도 30점**이 *"핵심 기능이 현장에서 정상 시연되는가"* 이고,
**발표역량 20점**이 *"데모 시연 순서가 명확한가"* 다. 시연 실패는 50점을 흔든다.

### 7.2 오프라인 완전 동작이 전제다

| 의존 | 대응 |
|---|---|
| 기상청 API | 키 부재 시 `fixtures/` 목업으로 **자동 폴백** (이미 설계됨) |
| 패키지 설치 | `pip install -r requirements.txt --no-index --find-links wheels/` |
| 외부 CDN | `web/` 은 외부 스크립트를 참조하지 않는다 |
| 인터넷 | **한 번도 필요하지 않다** |

### 7.3 시연 순서 (발표 중 3~4분)

발표 전체가 7~10분이라고 가정하고 시연에 3~4분을 쓴다. **영상과 순서가 다르다** —
현장에서는 "왜 이게 다른가"를 먼저 세우고 들어가야 질의응답이 쉬워진다.

| # | 길이 | 내용 | 노림수 |
|---|---|---|---|
| L1 | 30s | `--mode replay` 한 줄로 기동. 노드 3대가 붙는다 | 재현성을 첫 30초에 증명 |
| L2 | 60s | **기능 2** — 위반 주입 3종을 심사위원이 고르게 한다 | 시나리오가 아니라 도구임을 보임 |
| L3 | 40s | 실물 노드를 USB 로 연결 → `--mode hardware` 로 전환 → **같은 화면이 그대로 동작** | 전송 계층만 교체됨을 실시간 증명 |
| L4 | 50s | 기능 3 — 규칙 초안 생성 → **승인 거부** → 구동기 무반응 → 승인 → 동작 | 사람 검토 지점 (30점 항목) |
| L5 | 40s | 호스트 유닛테스트 + 검증기 8종 실행 | "빈 코드가 아니다" |

**L2 의 "심사위원이 고르게 한다"가 이 시연의 핵심 장치다.** 정해진 순서를 재생하는 것과
임의 입력에 반응하는 것은 다르다. 위반 8종 버튼을 모두 노출하고 선택을 넘긴다.

**L4 에서 승인을 먼저 거부하는 순서가 중요하다.** 승인 → 동작만 보이면 게이트가 있는지 알 수 없다.
거부 상태에서 구동기가 **움직이지 않는 것**을 먼저 보여야 게이트의 존재가 증명된다.

### 7.4 실패 폴백 4단계

| 단계 | 조건 | 전환 |
|---|---|---|
| 1 | 정상 | 실물 3종 + `--mode hardware` |
| 2 | 실물 결선 실패 | `--mode simulate` — 가상 노드가 양방향 응답 |
| 3 | 시뮬레이터도 실패 | `--mode replay` — 실측 로그 재생 (단방향이지만 기능 2는 완전히 동작) |
| 4 | PC 자체 문제 | **제출 영상 재생** + 코드 화면 설명 |

전환은 **명령 한 줄**이므로 무대에서 10초 안에 끝난다. 폴백이 있다는 사실 자체를 발표에서
언급하는 것이 낫다 — *"전송 계층만 교체되므로 어느 모드에서도 같은 코드가 돕니다"* 가
그대로 기술 설명이 된다.

### 7.5 예상 질의 대응

| 질문 | 답변 근거 |
|---|---|
| "표준을 어디에 썼는가" | `docs/standard-mapping.md` — 조항 ↔ 파일·라인 매핑. 화면에서 바로 연다 |
| "AI 가 만든 코드를 어떻게 검증했나" | `docs/ai-usage.md` + 검증기 8종 + 발견 사항 74건 기록(`fix_log/`) |
| "하드웨어 없이 정말 되는가" | 그 자리에서 `--mode replay` 재기동 |
| "표준에 문제가 있었다는 근거는" | `docs/standard-findings.md` 19건. 조항 번호와 원문 인용 포함 |
| "구동기가 임의로 움직일 수 있는가" | 입력 경로가 하나뿐임을 코드로 제시 (펌웨어 §6.6) + DB 트리거 4종 |
| "동작하지 않는 부분은" | **한계를 먼저 말한다** — `HALTED` 노드는 알릴 수단이 없다(F-076), UART 에서 `Payload Length` 위반은 즉시 탐지 불가(펌웨어 §5.5). 표준의 한계이지 구현 누락이 아님을 조항으로 설명 |

> 마지막 행이 배점에 직접 대응한다. 2차 평가는 *"질의응답에서 구현 근거·**한계**·보완 계획을
> 답변했는가"* 를 본다. 한계를 먼저 꺼내는 쪽이 유리하다.
