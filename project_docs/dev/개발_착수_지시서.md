## 0. 세션 시작

### 0.1 새 세션이 처음 하는 일

```bash
cd <저장소 루트>                 # ROLES.md · CLAUDE.md 가 있는 디렉터리
python tools/where.py            # 현재 단계 판정. 파일이 없으면 단계 0 이다
```

1. `ROLES.md` 에서 현재 역할이 작업자인지 확인한다
2. `CLAUDE.md` 를 읽는다 (21,000자)
3. **이 문서**를 읽는다 (16,000자)
4. `python tools/where.py` 로 **현재 단계**를 확인한다
5. §2.1 경로표에서 **그 단계의 읽을 문서만** 읽는다. 지정되지 않은 문서는 읽지 않는다

> 현재 단계를 **파일에 적어 두지 않는다.** 상태 파일은 갱신을 빠뜨리는 순간 실제와 갈린다
> (F-090·F-094). **출구 명령을 순서대로 돌려 처음 실패하는 단계가 현재 단계**다.
> `tools/where.py` 는 단계 0 에서 만든다.

## 1. 원칙

### 1.1 한 세션 = 한 단계

단계 출구 명령이 통과하기 전에는 **다음 단계의 파일을 만들지 않는다.**

### 1.2 출구 조건은 명령이다

완료 판정은 **복사해서 실행할 수 있는 명령**이다. "구현했다"가 아니라 "이 명령이 통과한다"가 완료다.

> `python` 이 3.11+ 를 가리키지 않으면 `python3` 로 읽는다. 모든 명령은 **저장소 루트에서** 실행한다.

### 1.3 설계서와 어긋나면 멈춘다

구현 중 설계서와 다르게 해야 할 이유를 발견하면 **코드를 먼저 바꾸지 않는다.**
`fix_log/` 에 기록하고 사용자에게 보고한다.

> 예외 없음. `contracts/` 는 여기에 더해 `CLAUDE.md` §5 절차(표준 조항 근거 + 사용자 확인)를 밟는다.

### 1.4 신설 검증기는 `CLAUDE.md` §6.2 를 지킨다

| 규칙 | 개발 단계에서의 의미 |
|---|---|
| 독립 입력 대조 (F-080) | 구현 파일 하나만 읽지 않는다. **구현 ↔ 설계 산출물** 최소 2개 |
| `required` 는 키만 본다 (F-091) | "함수가 존재한다"가 아니라 **호출해서 반환값을 본다** |
| 표준 구현 교차 검증 (F-095) | 자체 파서로 자기 코드를 읽으면 미구현 문법이 통과가 된다 |
| 목록 고정 금지 (F-094) | 검사 대상을 열거하지 않고 디렉터리 전수로 본다 |

### 1.5 실측값이 설계서의 추정치를 대체한다

펌웨어 설계서 §3.5 의 메모리 표는 추정치다. `avr-size` · `sizeof` 실측이 나오면 그 값으로 교체하고,
예산을 넘으면 코드가 아니라 **설계 결정**을 다시 본다. SRAM 예산은 **전체 globals(`avr-size` /
Arduino "Global variables use") 기준 55% 이하**다 — 단계 8 Uno 실측(50.0%)으로 애초의 "40%"가
펌웨어 데이터 슬라이스 추정 지표였음이 드러나(§3.4 표는 24.7%) 전체-globals 지표로 명문화했다
(2026-08-16, 펌웨어 설계서 §3.4). `tools/board_verify.py` 가 이 55% 를 실측 대조한다.

| **신설** | `tools/board_verify.py` — ① `core/` **소스 SHA-256** 이 3종 빌드에서 동일하고 보드 판별 매크로 0개, ② 플랫폼 헤더(`Arduino.h`·`WiFi.h`·`avr/*` 등)가 **보드 디렉터리에만** 있는가, ③ **AVR쌍**(Uno·Pro Mini, 둘 다 ATmega328P)에 한해 `avr-gcc` 로 컴파일한 `core.o` 해시 동일 — ESP32(Xtensa)는 ISA 가 달라 오브젝트가 원리상 일치할 수 없어 소스 해시로만 판정(펌웨어 설계서 §7.5.1·§11 이 정본이며, 이 문서 예전 판의 "오브젝트 해시 3종 동일" 표현을 그에 맞춰 정정한다), ④ `avr-size` 실측 ↔ 펌웨어 설계서 §3.5 표. `avr-gcc`/`avr-size` 부재 시 ①②는 항상 돌고 ③④는 `[SKIP]`(사람 실측)으로 남긴다 |

> **소스 SHA-256 동일 + 보드 판별 매크로 0개**가 "동일 응용계층" 주장의 기계 증거다.
> 조건부 컴파일(`#ifdef ARDUINO`·`#ifdef ESP32`·`#ifdef __AVR__`)이 하나만 들어가도
> 주장이 "분기가 있는 공통 코드"로 약해진다. AVR쌍의 `core.o` 동일은 여기에 얹는 강한
> 확증이지만 ESP32 는 다른 ISA 라 오브젝트 동일을 요구할 수 없다 — 그래서 3종 공통 증거는
> **소스** 해시이고(펌웨어 설계서 §7.5.1·§11), 오브젝트 해시는 AVR쌍 한정이다.
