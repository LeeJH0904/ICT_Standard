# `web/` 화면 설계서

> **대상**: `web/` — `index.html`(기능 1) · `verify.html`(기능 2) · `rules.html`(기능 3) · `settings.html`(설정)
> **입력**: `project_docs/api/openapi.json`(경로 22 · 오퍼레이션 23 · 쓰기 7) · `API_명세서.md` · `0937_요구사항_대조표.md` · `시연_시나리오.md`
> **검증**: `project_docs/web/web_verify.py` — 화면↔API↔조항 대응과 접근성 계약을 기계 대조한다
> **확정 사항**: 순수 바닐라(빌드 없음) · WCAG 2.1 AA 목표 · 설정 화면 포함

---

## 0. 이 문서가 결정하는 것

| 결정 | 값 | 근거 |
|---|---|---|
| 화면 수 | **4** (기능 3 + 설정 1) | §2 |
| 구현 방식 | **빌드 없는 순수 바닐라.** 번들러·CDN·`node_modules` 없음 | §1 |
| 데이터 흐름 | **SSE 단일 구독 → 화면별 필터.** 실패 시 1초 폴링 | §3.2 |
| 제어 입력 경로 | **POST 뿐.** 스트림으로 제어가 들어올 경로를 만들지 않는다 | §10 |
| 접근성 | **WCAG 2.1 AA 목표** + 기계 검증 가능한 8항목 | §8 |
| 신규 API | `PATCH /api/v1/device-property` 1건 (쓰기 4 → 5) | §9 |

**화면은 표준을 다시 해석하지 않는다.** 위반 판정도, 조항 번호도, RSC 이름도 전부 서버가 준 값을
그대로 렌더링한다(CLAUDE.md §3.4). 화면에 `switch (code) { case 9: "형식 오류" }` 가 등장하면
표준 해석이 두 곳에 생긴 것이다.

## 1. 왜 빌드가 없는가

| 제약 | 출처 | 결과 |
|---|---|---|
| 빌드 산출물·실행파일 커밋 금지 | 공고문 제출물 규격 | 번들 결과를 넣을 수 없다 |
| 재현성 필수 — "제출물만으로 실제 실행" | 공고문 (미충족 시 **서면 평가 제외**) | `npm install` 이 필요하면 재현 경로가 하나 늘어난다 |
| 오프라인 완전 동작 | CLAUDE.md §1-9 | 외부 CDN 참조 금지 |
| 소스코드 zip 200MB | 공고문 | `node_modules` 를 넣을 수 없다 |

```
web/
├── index.html          기능 1 — 대시보드
├── verify.html         기능 2 — 표준 준수 검증
├── rules.html          기능 3 — 규칙 · 승인 게이트
├── settings.html       설정 — 수집 주기 · 임계값
└── static/
    ├── app.css         공통 스타일 (단일 파일)
    ├── api.js          fetch 래퍼 · 오류 정규화
    ├── stream.js       SSE 구독 + 폴링 폴백
    ├── a11y.js         라이브 리전 · 포커스 관리
    └── fmt.js          hex · 시각 · 단위 포맷
```

**ES 모듈을 그대로 쓴다.** 각 페이지가 `<script type="module" src="static/api.js">` 형태로
필요한 모듈만 직접 불러온다 — 진입점 번들(`app.js`) 을 두지 않는다. 트랜스파일 없이 동작한다. 차트는 라이브러리 없이 **SVG 를 직접 그린다**(§4.3).

> **파일을 열면 소스가 그대로 보인다.** 심사자가 `verify.html` 을 열어 화면의 조항 번호가
> 어디서 왔는지 추적하면 `fetch('/api/v1/frames/violations')` 한 줄에 닿는다. 번들된
> 코드였다면 이 추적이 끊긴다 — **"표준 적용 지점을 명시할 것"**(공고문)과 직결된다.

## 2. 화면 4종 — 담당과 근거

| 화면 | 기능 | 담당 조항 | 배점 항목 | 영상 |
|---|---|---|---|---|
| `index.html` | 1 — 노드·디바이스 실시간 대시보드 | 0937 6.1 · 6.4 / 0943 8.1.1 | 구현완성도 15 | S3 (14s) |
| `verify.html` | 2 — 표준 준수 검증 | 0943 7.3.1 · 표 7-2·7-6·7-14 | **표준활용성 30** | **S4 (53s)** |
| `rules.html` | 3 — 규칙 초안·승인 게이트·실행 | 0937 6.3 · 6.5 / 부속서 A 3.2·3.3 | AI활용성 15 | S5 (17s) |
| `settings.html` | — 수집 주기·전송 모드 | 0937 6.4-2 / 부속서 A 1.3 | 공공편익 15 (접근성) | 미사용 |

**`settings.html` 은 영상에 넣지 않는다.** 117초 안에서 S4 를 53초로 지킨 결정(시연 §3.2)을
흔들지 않는다. 2차 발표 시연에서는 L3 앞에 20초를 쓸 수 있다 — 표준 필드가 화면에 그대로
노출되는 장면이라 질의응답에 유리하다.

### 2.1 화면 ↔ API 대응

| 화면 | 읽기 | 쓰기 |
|---|---|---|
| `index.html` | `listNodes` · `listNodeDevices` · `listTelemetry` · `listDeviceStates` · `listAlerts` · `streamEvents` | 없음 |
| `verify.html` | `listFrames` · `listViolations` · `getFrame` · `listAlerts` · `listNodes` · `streamEvents` | `injectVector` |
| `rules.html` | `listRules` · `getRule` · `listExecutions` · `listPublicDataRecords` · `listPublicDataSources` · `listNodes` · `listNodeDevices` · `streamEvents` | `createRuleDraft` · `approveRule` · `rejectRule` · `executeRule` · `manualControl` |
| `settings.html` | `listNodes` · `listNodeDevices` | `setDeviceProperty` |

**`index.html` 은 쓰기가 없다.** 관측 화면에서 운영 상태를 바꿀 수단을 두지 않는 것이 승인
게이트의 전제다.

**`verify.html` 의 `injectVector` 는 운영 상태를 바꾸지 않는다 (F-084).** 골든 벡터의 바이트를
**수신 경로**에 넣을 뿐이고, 결과는 다른 프레임과 똑같이 `frame_log` 에 기록된다. 장치·규칙·
실행 어느 것도 건드리지 않으며 `simulate`·`replay` 모드에서만 동작한다(§5.3-a).

> 초안은 이 화면을 "읽기 전용"으로 적었다. 그런데 §5.3 의 주입 버튼 8종이 브라우저에서
> 실행되어야 하고, **브라우저는 로컬 `sim/inject.py` 를 호출할 수 없다.** "읽기 전용"과
> "버튼 클릭"이 동시에 참일 수 없었다 — 표현을 **"운영 상태를 바꾸지 않는다"** 로 바로잡고
> 주입 경로를 계약으로 열었다.

## 3. 공통 셸

### 3.1 페이지 골격

```html
<body>
  <a class="skip" href="#main">본문으로 건너뛰기</a>   <!-- WCAG 2.4.1 -->
  <header>
    <nav aria-label="주 메뉴"> … 4개 링크, 현재 페이지에 aria-current="page" … </nav>
    <p id="conn" role="status">실시간 연결됨</p>       <!-- 3.2 연결 상태 -->
  </header>
  <main id="main"> … 화면별 … </main>
  <div id="live" aria-live="polite" class="sr-only"></div>  <!-- 8.3 -->
</body>
```

### 3.2 데이터 흐름 — SSE 단일 구독

```
                 ┌── node_up / node_down ──> index (토폴로지 → loadAll)
GET /stream ─────┼── frame ────────────────> index (값 갱신, 디바운스) · verify
 (1개 연결)      ├── violation ────────────> verify
                 ├── alert ────────────────> index · rules
                 └── execution ────────────> rules
                        │
             onerror ──> 1초 폴링 폴백 (아키텍처 §8.1)
                        └─> 연결 상태를 #conn 에 표시 (색 + 문자, §8.2)
```

> `index` 는 `frame` 도 구독한다 — 주기 센서값(NOTI_DEVICE_VALUE 등)은
> node_up/node_down 없이 계속 오므로, 이걸 듣지 않으면 값이 노드 연결/해제·알림
> 때만 갱신돼 "실시간 대시보드"가 되지 못한다. 프레임마다 전체 재조회하면
> 무거우므로 **800ms 디바운스로 값만**(토폴로지·로딩 표시 없이) 재조회한다.
> `frame` 소비는 읽기이므로 "관측 화면은 운영 상태를 바꾸지 않는다"(§2)와 무관하다.

| 규칙 | 내용 |
|---|---|
| 연결 수 | **화면당 1개.** `events=` 쿼리로 필요한 종류만 구독한다 |
| 폴백 | `onerror` → 1초 폴링. **자동 전환하고 사용자에게 알린다** — 조용히 바뀌면 실시간인 줄 안다 |
| 재연결 | 지수 백오프 1·2·4·8초, 상한 8초. 복구 시 폴링 중단 |
| 누락 보정 | 폴백 중 놓친 프레임은 재연결 직후 `listFrames?since=` 로 채운다 |
| 상태 표시 | `실시간 연결됨` / `폴링 중 (1초)` / `연결 끊김` 3종. **색과 문자를 함께** 쓴다 |

> **SSE 는 단방향이다.** 제어 명령이 스트림으로 들어올 경로는 만들지 않는다
> (CLAUDE.md §1-7). 화면의 모든 상태 변경은 `POST`/`PATCH` 다.

### 3.3 화면 상태 모델

각 화면은 네 상태를 갖고, **넷 다 화면에 표시된다.**

| 상태 | 표시 | 이유 |
|---|---|---|
| `loading` | 스켈레톤 + `aria-busy="true"` | 빈 화면과 구분 |
| `empty` | "아직 수신한 프레임이 없습니다" 같은 **원인 문장** | 고장과 구분 |
| `error` | 오류 코드 + 조항/제약 이름 (`Problem` 스키마) | API §4.5 가 준 값을 그대로 |
| `ready` | 내용 | |

**`empty` 를 `loading` 처럼 보이게 두지 않는다.** 심사자가 replay 모드로 처음 열면 데이터가
없는 것이 정상이며, 그때 무엇을 기다리는지 화면이 말해야 한다.

## 4. `index.html` — 기능 1 대시보드

### 4.1 구성

```
┌ 노드 3 · 디바이스 8 · 알림 2 ──────────────────────┐  요약 바
├──────────────────────────────────────────────────┤
│ [노드 카드]  Node 0x00003  UART  S/W 0x10  NORMAL │  ← 카드는 데이터로 생성
│   온도  25.3 ℃   ▁▂▃▅▃▂  60s 전                  │
│   습도  61.0 %    ▂▃▄▃▂▁  60s 전                  │
│   토양수분장력 …                                   │
├──────────────────────────────────────────────────┤
│ [알림]  ERROR_BATTERY_LOW (0x07) — 7.3.2절        │
└──────────────────────────────────────────────────┘
```

### 4.2 노드 종류를 화면이 알지 않는다 (CLAUDE.md §1-6)

```js
// ○ 서버가 준 것만 쓴다. Device 스키마의 필드명 그대로다
card.querySelector('.subtype').textContent = dev.subtype;      // 서버가 레지스트리에서 조회한 이름
card.querySelector('.code').textContent    = dev.siap_subtype; // 0943 표 7-14 원시 코드 (표시용)
// ✕ 화면에 종류 테이블을 두지 않는다
// const NAMES = {1:'온도', 2:'습도', ...}
```

> **`subtype` 과 `siap_subtype` 은 다른 필드다.** 앞은 서버가 레지스트리에서 조회한 **이름**,
> 뒤는 표 7-14 의 **원시 코드**다. 화면은 둘 다 서버에서 받는다 — 코드에서 이름을 만들지 않는다.

**판정 방법**: `web/` 전체에서 `Subtype` 코드값(0x01·0x85 등)이나 한국어 종류명이 **상수로**
등장하면 안 된다. 새 종류의 노드를 붙였을 때 화면 코드를 고쳐야 한다면 "서버 코드 수정 0줄"
주장의 절반이 무너진다. `web_verify.py` 가 검사한다.

### 4.3 스파크라인은 SVG 를 직접 그린다

```js
// 값 배열 -> polyline points. 라이브러리 없음
const pts = vals.map((v,i) => `${i*w},${h - (v-min)/(max-min)*h}`).join(' ');
```

| 항목 | 결정 |
|---|---|
| 크기 | 120 × 24 px |
| 접근성 | `role="img"` + `aria-label="최근 10분 온도 추이, 최소 24.1, 최대 26.0"` — **그래프를 문장으로도 준다** |
| 색 | 선 하나. 색으로 의미를 구분하지 않는다 |

## 5. `verify.html` — 기능 2 표준 준수 검증 ★

**영상 53초와 발표 60초가 이 화면이다.** 배점 최대 항목(표준활용성 30)을 혼자 담당한다.

### 5.1 구성 — 3분할

```
┌ 주입·프레임 ─────┬ 원문 hex ────────────┬ 판정 ──────────────┐
│ [주입 8종 고정]  │ 12 00 00 00 01 00    │ ✔ 정상             │
│ 1 Version  2 Node│                      │                    │
│ 3 Length   4 Type│ ┌ 필드 분해 ───────┐ │ INVALID_FORMAT     │
│ 5 Trans.   6 Value│ │ Version    8bit  │ │ (0x09) — 7.3.1절   │
│ 7 Subtype  8 NEC │ │  = 0x12  (v1.2)  │ │                    │
│ ──────────────── │ │ Message Type 14b │ │ Payload Length=24, │
│ 프레임 목록 [위반]│ │  = 0x0000        │ │ 실제 수신 18byte    │
│ ▸ f-101 정상     │ │  ↑ 바이트 경계   │ │                    │
│ ▸ f-102 위반 ⚠   │ │    을 넘는 필드  │ │ [표준 원문 위치]    │
│ ▸ f-103 알림 ●   │ └──────────────────┘ │ 0943 7.3.1 · 표7-2 │
│ ↕ 목록만 스크롤  │                      │                    │
└──────────────────┴──────────────────────┴────────────────────┘
```

주입 8종은 왼쪽 패널 상단에 고정하고 프레임 목록만 고정 높이 안에서 세로
스크롤한다. 프레임 누적으로 시연 조작 버튼의 위치가 바뀌어서는 안 된다.
"위반만 보기"는 최초 조회·1초 폴링·SSE 실시간 수신·재연결 복구에 같은
`judgement == violation` 조건을 적용한다.

### 5.2 이 화면이 증명하는 것

| 증명 | 화면 요소 |
|---|---|
| 표준의 비트 레이아웃을 실제로 구현했다 | 필드 분해 패널 — 각 필드의 **비트 폭과 오프셋**을 함께 보인다 |
| 바이트 경계를 넘는 필드를 다룬다 | `Message Type`(14bit) · `GCG/Node ID`(20bit) · `Subtype`(9~16bit) 을 hex 위에서 **색 + 밑줄**로 표시 |
| 위반을 조항으로 판정한다 | 판정 패널이 `코드명(0x??) — N절` 을 그대로 출력 |
| 판정이 서버 것이다 | 화면에 판정 로직 없음 (§10) |

**그러려면 서버가 분해 결과를 줘야 한다 (F-085).** 초안은 "화면이 필드 폭·오프셋을 표시한다"와
"화면은 비트를 자르지 않는다"를 동시에 적었는데, `Frame` 응답에 `raw_hex` 와 헤더 7필드밖에
없었다. **둘 다 참일 수 없었다.**

| 응답 필드 | 내용 | 화면 |
|---|---|---|
| `Frame.fields[]` | `FieldSlice(name, bit_offset, bit_width, raw, display, element, clause)` | 필드 분해 패널 · hex 하이라이트 |
| `Frame.judgement` | `normal` / `violation` / `alert` | 목록 아이콘·색 (F-060) |
| `Alert.frame_id` | 알림을 유발한 프레임 | `X08` 알림을 원본 프레임과 결속 |

`fields` 는 **헤더 7필드 + 고정부 + 가변 요소 N개분 전체**다. 화면은 `bit_offset`·`bit_width` 로
hex 위 하이라이트 범위를 계산할 뿐이며, **바이트 경계를 넘는 필드도 서버가 준 오프셋 그대로**
칠한다 — 화면이 14bit·20bit 를 다시 해석하지 않는다.

> `fields` 와 `judgement` 는 **저장하지 않는다.** 같은 바이트에서 코덱이 언제든 다시 만들 수
> 있고, 저장하면 코덱과 DB 가 갈릴 수 있다. `api_verify.py` 의 유도 필드 예외에 근거를 적었다.

### 5.3 주입 버튼 8종

시연 §3.1 의 위반 8종과 **1:1** 이다. 골든 벡터 `X01`~`X08` 의 hex 를 그대로 흘려보낸다.

| # | 라벨 | 골든 | 기대 출력 |
|---|---|---|---|
| 1 | `Version` 조작 | `X01` | `INVALID_VERSION (0x01) — 7.3.1절` |
| 2 | 미등록 `Node ID` | `X02` | `INVALID_NODE_ID (0x03) — 7.3.1절` |
| 3 | `Payload Length` 불일치 | `X03` | `INVALID_FORMAT (0x09) — 7.3.1절` |
| 4 | `Message Type` = 0x000E | `X04` | `INVALID_FORMAT (0x09) — 표 7-2` |
| 5 | `Transmission Type` = 0x03 | `X05` | `INVALID_TRANSMISSION_TYPE (0x08) — 표 7-6` |
| 6 | `Value Type` = 0x03 | `X06` | `INVALID_DATA_TYPE (0x06) — 표 7-14` |
| 7 | 미등록 `Subtype` | `X07` | `INVALID_DATA_SUBTYPE (0x07) — 표 7-14` |
| 8 | `NEC` 배터리 저전력 | `X08` | `ERROR_BATTERY_LOW (0x07) — 7.3.2절` **위반 아님 · 알림** |

> **8번을 위반과 다른 색·다른 아이콘으로 표시한다.** F-060 이 만든 구분(`judgement`:
> `violation` / `alert` / `normal`)이 화면까지 이어져야 한다. 정상 알림을 붉게 칠하면
> 서버가 애써 나눈 것을 화면이 되돌린다.

**주입은 화면이 만들지 않는다.** 버튼은 `sim/inject.py` 에 벡터 ID 를 요청할 뿐이고,
바이트는 `contracts/vectors/golden.jsonl` 에서 온다 — **영상 속 hex 와 제출 벡터가 같아야**
공고문의 "진위·창작성" 조항을 통과한다(시연 §3.1).

### 5.3-a 주입 경로 — `POST /api/v1/sim/inject` (F-084)

브라우저는 로컬 Python 모듈을 호출할 수 없다. 버튼이 실제로 실행되려면 HTTP 경로가 있어야 한다.

| 항목 | 결정 | 이유 |
|---|---|---|
| 본문 | **벡터 ID 열거만** (`X01`~`X08`) | 임의 hex 를 받으면 "제출 벡터와 영상 hex 가 같다"가 깨진다 |
| 바이트 출처 | `contracts/vectors/golden.jsonl` | 서버가 ID 로 조회한다. 화면도 서버도 바이트를 만들지 않는다 |
| 모드 제한 | `simulate` · `replay` 만 **202**. `hardware` 는 **409** | 실물 링크에 조작 프레임을 흘리면 실측 로그의 신뢰성이 깨진다 (CLAUDE.md §1-1) |
| 방향 | 골든 `X01`~`X08` 은 전부 **`N->G` 수신 방향** | 구동기로 가는 경로가 아니다 (§1-7 무관) |
| 결과 전달 | SSE `frame` · `violation` | 주입 응답이 아니라 **평소와 같은 경로**로 온다 — 시연에서 실제 수신과 구분되지 않아야 한다 |
| 기록 | `frame_log` · `frame_violation` | 다른 프레임과 같은 방식. 주입분만 따로 숨기지 않는다 |

> **2차 발표에서 심사위원이 8종 중 하나를 고른다**(시연 §7.3 L2). 정해진 순서를 재생하는 것과
> 임의 입력에 반응하는 것은 다르며, 후자만이 "시나리오가 아니라 도구"임을 보인다. 그 조작이
> 성립하려면 버튼이 눌리는 순간 서버가 응답해야 한다.

### 5.4 hex 뷰

| 항목 | 결정 |
|---|---|
| 표기 | 2자리 대문자 hex, 8 byte 씩 줄바꿈, 오프셋 표기 |
| 필드 하이라이트 | 필드 선택 시 해당 **비트 범위**를 강조. 바이트를 반씩 쓰는 필드는 반쪽만 칠한다 |
| 색 의존 금지 | 하이라이트에 **밑줄과 굵기**를 함께 준다 (§8.2) |
| 복사 | hex 전체 복사 버튼 — 심사자가 제출 로그와 대조할 수 있게 |

## 6. `rules.html` — 기능 3 규칙·승인 게이트

### 6.1 승인 게이트가 화면의 주인공이다

```
① 입력            ② 초안              ③ 승인            ④ 실행
공공데이터   ──>  AI 초안 생성   ──>  사람 검토   ──>  구동기
기상청 예보       (자연어)            승인/거부         REQ_SET_DEVICE_CONTROL
                       │                  │
                  action_json 없음    action_json + 대상 확정
```

| 단계 | 화면 | 호출 | 표준 근거 |
|---|---|---|---|
| ① | 기상청 예보 카드 (출처·수집시각 표시) | `listPublicDataRecords` | 0937 6.2 · 부속서 A 2.3 |
| ② | 초안 생성 + **"미승인" 배지** | `createRuleDraft` | 0937 6.3 · A.3-5 |
| ③ | 승인 / **거부** + 대상 장치 선택 | `approveRule` · `rejectRule` | **A.3.2 절차 3** |
| ④ | 실행 결과 (RSC) | `executeRule` | 0937 6.5 · 0943 8.1.5 |

### 6.1-a 초안을 클라이언트가 쓰지 않는다 (F-083)

초안은 **서버가 모델을 돌려** 만든다. `createRuleDraft` 는 `origin` + `model_id` + `inputs` 를
받고, 서버가 `mms.run_model()` 을 호출해 `draft_text` 를 만들어 저장한다.

| `origin` | 보내는 것 | 서버가 하는 일 |
|---|---|---|
| `AI_DRAFT` | `model_id` · `inputs` (**`draft_text` 금지**) | `mms.run_model()` 실행 → `draft_text` 생성 |
| `WIZARD` · `SCRIPT` | `draft_text` | 그대로 저장 (0937 A.3-5 위자드·스크립트 입력) |

> **클라이언트가 쓴 문장을 `AI_DRAFT` 로 저장하면 실제 AI 실행 증거가 사라진다.** 그러면
> 공모전의 "생성형 AI 활용" 주장이 화면 문구에만 남는다. 스키마의 `if/then` 이 `AI_DRAFT` 에
> `draft_text` 를 넣지 못하게 막는다.

**`Rule.generation`** 이 실제 경로를 돌려준다 — `AI` / `THRESHOLD_FALLBACK` / `WIZARD` / `SCRIPT`.
AI 제공자 부재로 폴백했으면 화면이 그대로 표시한다(§6.3). `origin` 은 요청자의 **의도**이고
`generation` 은 서버가 실행한 **결과**다. `control_rule` 이 두 값을 따로 보관하며,
`origin='AI_DRAFT'` 이면 `generation` 이 `AI` 또는 `THRESHOLD_FALLBACK` 이어야 한다는 CHECK 가 있다.

### 6.2 미승인 상태를 화면이 숨기지 않는다

| 규칙 | 이유 |
|---|---|
| 미승인 규칙에 **실행 버튼을 렌더링하지 않는다** — `disabled` 가 아니라 없다 | `disabled` 는 DOM 조작으로 풀린다. 서버 트리거가 최종 방어선이지만 화면도 경로를 만들지 않는다 |
| 미승인 배지는 색 + **문자**("미승인") | §8.2 |
| 승인 시 **무엇을 승인하는지** 다시 보여준다 — 조건·명령·대상 장치 3종 | F-039 · F-049 가 만든 3중 결속의 화면 대응 |
| 승인 후 초안 텍스트는 **읽기 전용** | `control_rule` 트리거가 불변을 강제한다. 화면이 편집 가능하게 두면 400 을 받는다 |
| **거부는 사유 입력이 필수다** | `RejectRequest.reason` 이 `minLength: 1`. 사유 없는 반려는 검토 기록이 되지 못한다 |
| 거부된 규칙은 **거부 배지 + 사유**를 표시하고 승인 버튼을 렌더링하지 않는다 | 거부는 되돌릴 수 없다 — 배타 CHECK `approved_at IS NULL OR rejected_at IS NULL` (F-091: 실제 DDL 이름으로 정정) |
| 거부된 규칙을 목록에서 숨기지 않는다 | **거부 사실이 남아야 "사람 검토 지점"이 증거가 된다**(2차 평가 30점 항목) |

**거부를 영속 상태로 둔 이유 (F-083).** 초안은 거부를 화면 상태로만 두었다. 그러면 초안 생성
직후와 거부 후가 DB 에서 구별되지 않아, 시연에서 "거부했다"를 보일 수단이 화면뿐이다.
`control_rule` 에 `rejected_at` · `rejected_by` · `reject_reason` 을 두고 **거부 관련 CHECK 4종**
(거부자 동시성 · 사유 동시성 · 사유 공백 금지 · 승인과 배타) 과 **트리거 1종**(`trg_rule_reject_immutable`)
으로 강제한다. 셋은 각각 결함 주입으로 제거 시 테스트가 뒤집히는 것을 확인했다.

> **초안은 "CHECK 3종 · 트리거 3종"이라 적었고 DDL 과 달랐다 (F-091).** F-083 처리 중
> 독립 반례가 없는 트리거 2종을 제거했는데 이 문장을 함께 고치지 않았다. 문서가 DDL 보다
> 강한 보장을 주장하면 구현자가 확인하지 않고 넘어간다 — `meta_verify.py` 가 이제
> 제약 개수 주장을 실제 DDL 과 대조한다.

> **시연은 거부를 먼저 보여준다**(시연 §7.3 L4). 승인 → 동작만 보이면 게이트가 있는지 알 수
> 없다. 거부 상태에서 구동기가 움직이지 않는 것을 먼저 보여야 게이트가 증명된다.

### 6.3 AI 산출물임을 화면이 표시한다

초안 카드에 **`생성형 AI 초안 — 사람 검토 필요`** 를 항상 표시한다. 공고문 평가기준의
*"오류·환각 대응 및 사람 검토 지점이 설명되는가"*(2차 30점)에 대한 화면상의 답이다.
AI 제공자 부재로 `threshold` 폴백이 쓰였으면 **그 사실도 표시**한다 — 어느 경로로 만들어진
초안인지 화면이 숨기지 않는다.

## 7. `settings.html` — 수집 주기·전송 모드

### 7.1 이 화면이 닫는 조항

| 조항 | 요구 | 화면 |
|---|---|---|
| 0937 6.4-2 | 수집 주기 및 **구역**을 지정하여 수집 | 구역 선택 + 일괄 적용 |
| 부속서 A 1.3 | **사용자가** 데이터 수집 주기를 지정 | `Period` 입력 |

> **화면은 `Transfer Mode` · `Period` 두 필드만 노출한다 (축소 결정, 2026-08-18 사용자 확인).**
> 이전 판은 `Lower/Upper Value` 임계 입력도 두어 부속서 A 1.5(알림 기준값)를 겨냥했으나,
> ① 이 두 값은 저장 시 `lower_limit`·`upper_limit`(장치 물리 특성) 컬럼에 얹혀 물리 유효범위와
> 뜻이 겹치고, ② 시뮬레이션의 센서값이 골든 벡터로 고정이라 임계 교차 이벤트가 발생하지 않아
> 화면에서 효과를 확인할 방법이 없다. **혼동만 주고 시연으로 증명할 수 없는 입력이라 화면에서
> 덜어냈다.** A.1-5 는 원래 이 화면으로 닫히지 않았고(§9 각주), 임계 입력 제거로 조항 집계는
> 바뀌지 않는다. **표 7-15 4필드 쓰기 능력 자체는 API·프로토콜 계층에 그대로 남는다** —
> `DevicePropertyPatch` 는 여전히 `lower_value`·`upper_value` 를 받는다(§7.3·§9).

### 7.2 구성

```
대상  ( ) 디바이스 개별   (•) 구역 일괄
      온실 [1번 온실 ▾]  위치 [동쪽 ▾]  종류 [온도 ▾]   → 대상 3대

설정  전송 모드  ( ) 주기  (•) 이벤트  ( ) 둘 다      ← 표 7-15 Transfer Mode (2bit)
      수집 주기  [   60 ] 초    0 ~ 16383            ← 표 7-15 Period (14bit)

      [적용]  →  PATCH /api/v1/device-property   (본문: transfer_mode · period_sec)
                 →  0943 8.1.3.2 REQ_SET_DEVICE_PROPERTY
```

**입력 옆에 표준 필드명과 비트 폭을 함께 적는다.** 이 화면은 표준 필드를 사용자에게 직접
노출하는 유일한 지점이며, 심사자가 "표준이 어디에 반영되었는가"를 화면만 보고 확인할 수 있다.

### 7.3 이 화면이 제어값을 쓰지 않는다

| 표 7-15 필드 | 화면 | API(`DevicePropertyPatch`) | 이유 |
|---|---|---|---|
| `Transfer Mode` · `Period` | **입력** | 받음 | 사용자가 정하는 수집 정책. 화면에 그대로 노출 |
| `Lower Value` · `Upper Value` | 노출 안 함 | 받음 | 표 7-15 쓰기 능력은 계약에 남기되(§7.1 축소 각주) 화면에서만 덜어냄 |
| `Lower Limit` · `Upper Limit` · `Precision` | 읽기만 | — | 장치의 물리 특성 (1369-P1 6.3.2). 설치 시 확정 |
| `Status` | 읽기만 | — | 노드가 보고한다 |
| `DEVICE_MAIN_INFO.Value` | **쓰지 않음** | 없음 | **제어값이다.** 여기서 쓰면 승인 게이트를 우회하는 구동 경로가 생긴다 (CLAUDE.md §1-7) |

`DevicePropertyPatch` 스키마는 **4개 필드**(`transfer_mode` · `period_sec` · `lower_value` · `upper_value`)를
받고 `additionalProperties: false` 다 — 화면이 그중 2개만 보내더라도 계약은 표 7-15 준수를 위해
4필드를 유지한다. `api_verify.py` 가 `value` 계열(제어값) 필드의 **부재**를 검사한다.

## 8. 접근성 — WCAG 2.1 AA

1차 평가 *"공공편익·포용성 — 사회적 약자·디지털 취약계층 접근성"* **15점** 항목의 대응이다.

### 8.1 왜 이 프로젝트에서 특히 중요한가

**기능 2 는 위반을 붉은색으로 표시한다.** 색에만 의존하면 색각 이상 사용자에게 **화면의 핵심
정보가 전달되지 않는다** — 정상 프레임과 위반 프레임을 구분할 수 없으므로 기능 자체가
무의미해진다. 접근성이 부가 기능이 아니라 **기능 2 의 성립 조건**이다.

### 8.2 색에만 의존하지 않는다 (WCAG 1.4.1)

| 의미 | 색 | 함께 주는 것 |
|---|---|---|
| 정상 프레임 | 회색 | `✔` + "정상" |
| 위반 프레임 | 적색 | `⚠` + "위반" + **코드명·조항** |
| 알림(NEC) | 황색 | `●` + "알림" |
| 노드 온라인 | 녹색 | "연결됨" |
| 노드 STALE | 황색 | "응답 없음 (60초)" |
| 미승인 규칙 | 회색 | "미승인" 배지 |

### 8.3 기계로 검증 가능한 8항목

`web_verify.py` 가 검사한다. **검증할 수 없는 항목은 목표로만 적고 검사 대상에 넣지 않는다** —
"WCAG AA 준수"를 근거 없이 주장하지 않기 위해서다.

| # | 항목 | WCAG | 검사 방법 |
|---|---|---|---|
| 1 | 모든 페이지에 `lang="ko"` | 3.1.1 | 속성 존재 |
| 2 | `<main>` · `<nav>` · `<header>` 랜드마크 | 1.3.1 | 태그 존재 |
| 3 | 본문 건너뛰기 링크가 첫 포커스 요소 | 2.4.1 | `.skip` 이 `<body>` 첫 자식 |
| 4 | 모든 `<img>` · `role="img"` 에 대체 텍스트 | 1.1.1 | `alt` / `aria-label` 존재 |
| 5 | 모든 폼 입력에 연결된 `<label>` | 3.3.2 | `for` ↔ `id` 대응 |
| 6 | 실시간 갱신 영역에 `aria-live` | 4.1.3 | 속성 존재 |
| 7 | 상태 표시가 색 외 텍스트를 동반 | 1.4.1 | 상태 클래스에 텍스트 노드 |
| 8 | 명도대비 4.5:1 (CSS 변수 조합) | 1.4.3 | `app.css` 의 색 변수쌍을 계산 |

**8번은 실제로 계산한다.** `--fg-*` / `--bg-*` 변수쌍의 상대 휘도비를 구해 4.5 미만이면 FAIL.
색을 고르다 대비가 무너지는 것이 가장 흔한 회귀다.

### 8.4 키보드 조작 (WCAG 2.1.1)

| 화면 | 키보드만으로 가능해야 하는 것 |
|---|---|
| `verify.html` | 프레임 선택 · **주입 8종 실행** · 필드 선택 · hex 복사 |
| `rules.html` | 초안 생성 · **승인/거부** · 실행 |
| `settings.html` | 대상 선택 · 전 항목 입력 · 적용 |

마우스 전용 상호작용(드래그·호버 전용 메뉴)을 두지 않는다. 포커스 표시는
`:focus-visible` 로 **2px 외곽선**을 준다 — 브라우저 기본을 지우지 않는다.

## 9. 신규 API — `PATCH /api/v1/device-property`

설정 화면 때문에 쓰기 경로가 **4 → 5** 로 늘었다. 늘린 이유와 막은 것을 함께 적는다.

| 항목 | 내용 |
|---|---|
| 경로 | `PATCH /api/v1/device-property` · `operationId: setDeviceProperty` · 태그 `ems` |
| 선택자 | `install_id` (개별) **또는** `greenhouse_id` (구역 일괄 = 온실 전체). `install_location` · `subtype` 은 구역을 좁히는 **선택 항목**이며 단독으로는 대상을 정하지 못한다. 둘은 배타 (F-093) |
| 본문 | `transfer_mode` · `period_sec` · `lower_value` · `upper_value` **4개만** (표 7-15 준수 계약. 화면은 이 중 앞 2개만 전송 — §7.1 축소 각주) |
| 나가는 프레임 | 0943 8.1.3.2 `REQ_SET_DEVICE_PROPERTY` |
| 실패 의미 | 구역 일괄 중 대상 하나라도 `Value Type` 이 맞지 않으면 **전량 거부 422** (`Problem.siap_rsc = INVALID_DATA_TYPE`). 부분 적용은 어느 장치까지 적용됐는지 화면이 되물을 수단이 없다 (F-093) |
| 막은 것 | `Value` 계열 필드 없음 · `additionalProperties: false` · 선택자 4필드 모두 **non-nullable**(F-093 — nullable 이면 `{"install_id": null}` 이 `required` 를 통과한다) · `api_verify.py` 가 실제 JSON Schema 반례로 검사 |
| 왜 경로 하나인가 | 쓰기 경로가 늘수록 승인 게이트 주변의 검증 표면이 넓어진다. 선택자 하나로 개별·일괄을 모두 덮는다 |

**0937 대조표에 미치는 영향**: `⚠ 부분` 이던 **6.4-2 · A.1-3 두 건**이 닫힌다. §5-3 후속 과제가
사라지고, 6장 판정이 `✅ 20 / ⚠ 7` → **`✅ 21 / ⚠ 6`** 이 된다.

> **A.1-5 는 닫히지 않는다 (F-087 · F-094).** 이 화면은 이제 임계값 입력을 아예 두지 않는다
> (§7.1 축소 결정) — 예전에 임계 입력이 있던 때에도 닫지 못했다. 0937 부속서 A 1.3 이 요구하는
> **알림 발송 시간** 입력이 없고, 표 7-15 의 Event 전송은 장치→**제어기** 조건일 뿐
> **제어기→사용자** 알림이 아니다. 부속서 A 집계는 `✅ 16 / ⚠ 5 / ❌ 10` 그대로이며
> 남은 것은 대조표 §5-6 이다. 임계 입력 제거는 이 집계를 바꾸지 않는다 —
> A.1-5 는 이 화면 밖에서 닫아야 한다.
> 이 문장은 한 번 "닫힌다"로 적었다가 F-094 로 되돌렸다 — 정본은 대조표 §3.5 다.
