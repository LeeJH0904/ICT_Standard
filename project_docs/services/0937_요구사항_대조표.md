# TTAK.KO-10.0937 요구사항 대조표

> **표준**: TTAK.KO-10.0937 — 클라우드 기반 스마트팜 서비스 요구사항
> **대상**: `backend/services/` (ems · dms · mms · fms · fcs)
> **검증**: `project_docs/services/services_verify.py` — 대조표의 집계와 조항 커버리지를 기계 대조한다
> **제출**: 패키징 시 `docs/0937-requirements-matrix.md` 로 이관한다 (실행계획 §11 제출물 목록)

이 문서는 **표준 3종 중 0937 의 활용성 근거**다. 0943 은 골든 벡터 53건이, 1369-P1 은 스키마 제약
98종이 준수 근거를 만든다. 0937 은 요구사항 문서라 실행 가능한 벡터가 없으므로, **조항 대 구현의
전수 대조표가 그 자리를 대신한다.**

---

## 0. 표기 규약

표준 원문의 서술어를 그대로 강도로 옮긴다. 임의로 격상·격하하지 않는다.

| 표기 | 원문 서술어 | 의미 |
|---|---|---|
| **필수(능력)** | "~할 수 있어야 한다" · **"~가능해야 한다"** | 기능이 존재해야 한다 |
| **필수** | 위에 해당하지 않으면서 "~해야 한다" 로 끝남 | 구현하지 않으면 표준 미준수 |
| 선택 | "~할 수 있다" · "~할 수도 있다" · "지원할 수 있다" · "~가능할 수 있다" | 구현 여부가 준수에 영향 없음 |

> **적용 순서가 있다 (F-081).** 초안은 `"~가능해야 한다"` 를 규약에 넣지 않아 7건을 `필수` 로
> 잘못 올렸다. `"등록·변경·삭제 및 연결이 **가능해야 한다**"`(6.1-1)는 "해야 한다"로 끝나지만
> 요구하는 것은 **능력**이다. 능력 표현을 먼저 보고, 남은 것만 `필수` 로 본다.
>
> 강도의 정본은 이 표가 아니라 **`0937_clauses.json`** 이다. 원문 종결어미 33건을 옮겨 둔
> 독립 입력이며, `services_verify.py` 가 그것에서 강도를 재산출해 아래 표와 대조한다.

| 판정 | 의미 |
|---|---|
| ✅ 설계 대응 | **설계 산출물**(스키마 컬럼 · API 경로 · 모듈 진입점)에 요구 전체를 수행하는 경로가 닫혀 있다 |
| ⚠ 부분 | 요구의 일부만 닫힌다. **무엇이 열려 있는지 적는다** |
| ❌ 범위 외 | 구현하지 않는다. **사유를 적는다** |

> **현재 단계는 구현 전이다 (F-082).** 그래서 `✅` 는 "동작한다"가 아니라 **"설계가 닫혀 있다"**
> 를 뜻한다. 이 구분을 두지 않으면, 테이블만 있고 진입점이 없는 조항이 충족으로 굳는다 —
> 초안에서 실제로 6건이 그렇게 되어 있었다. 구현 후에는 `backend/tests/` 통과가 판정 근거가 된다.
>
> `services_verify.py` 는 `✅` 행의 근거 심벌을 **`schema.sql` · `openapi.json` · §4.1 진입점표**
> 에서 실제로 찾는다. 존재하지 않는 심벌을 적으면 FAIL 한다.

> **범위 외를 숨기지 않는다.** 6개 서비스 중 5개만 구현한다는 사실을 심사자가 표에서 바로 보는 편이,
> 발표 질의에서 드러나는 것보다 낫다. 2차 평가는 *"한계·보완 계획을 답변했는가"* 를 배점에 둔다.

## 2. 구현 범위 선언 — 무엇을 왜 제외했는가

### 2.1 FOS (6.6) 를 구현하지 않는다

**사유**: FOS 는 영농일지·농자재·경영정보를 다루는 **농장 경영 서비스**다. 이 프로젝트가 증명하려는
것은 CLAUDE.md §0 의 네 주장 — MCU 3종 혼용 · 하드웨어 없는 표준 검증 · 노드 추가 시 서버 코드
0줄 · 표준 장애 지점 발견 — 이며, FOS 는 그중 어느 것과도 접점이 없다.

**대신 6.6-1 은 충족한다.** 농가·시설하우스·영역 식별자 체계는 1369-P1 참조모델에서 이미
`farm_info` · `greenhouse_info` 로 구현되어 있다. **FOS 의 데이터 기반은 있고 업무 기능만 없다**는
것이 정확한 서술이다.

### 2.2 부속서 A.4 (써드파티 지원 서비스) 를 구현하지 않는다

부속서 A 의 네 시나리오는 **누적 구조**다 — 원격제어는 수동제어를 포함하고, 자동제어는 원격제어를,
써드파티는 자동제어를 포함한다.

```
A.1 수동제어  ⊂  A.2 원격제어  ⊂  A.3 자동제어  ⊂  A.4 써드파티
   (5건)          (+9건)          (+11건)          (+6건)
   ────────────── 본 구현 대상 ──────────────┘      범위 외
```

**본 구현은 A.3 자동제어까지를 대상으로 한다.** A.4 는 외부 개발자에게 데이터·모델을 개방하고
사용량을 집계·과금하는 플랫폼 운영 영역이다. 개방하지 않으므로 6.3-9(사용량 집계)도 함께 범위 외가
된다 — **두 제외가 같은 결정에서 나온다.**

### 2.3 6.1-4 (펌웨어 업그레이드) 는 표준 조합으로 불가능하다

0943 의 메시지 34종에 **바이너리 전송 수단이 없다.** `REQ_SET_REBOOT`(8.1.6)로 재시작은 시킬 수
있으나 이미지를 내려보낼 메시지가 정의되어 있지 않다. 0937 이 요구하고 0943 이 수단을 주지 않는
지점이며, 표준 조합의 빈틈이다.

> **이것은 표준결함으로 등재하지 않는다.** 0937 이 "지원할 수 **있다**"(선택)로 적었고,
> 0943 의 적용 범위(§1)가 펌웨어 배포를 다루지 않는다고 명시하지도 않았다. 두 표준이 서로를
> 인용하지 않으므로 **불일치가 아니라 미연결**이다. `docs/standard-findings.md` 의 "표준 간
> 미연결" 항목으로만 기록한다.

### 4.4 F-082 로 추가한 설계 계약 2종

초안은 테이블이 있으면 조항이 닫힌 것으로 셌다. **저장 형태와 실행 경로는 다르다.** 두 조항은

#### 4.4-a `mms.run_model(model_id, inputs) -> RuleDraft` (6.3-6)

```python
def run_model(model_id: str, inputs: dict) -> RuleDraft:
    """control_model.exec_method 가 지정한 방법으로 모델을 구동하고 출력을 받는다.
       0937 6.3-6 — '메타정보에 등록된 모델 실행 방법에 따라 모델을 구동하고

```

| 항목 | 값 |
|---|---|
| 입력 | `control_model.input_spec` 이 선언한 키. 공공데이터는 `public_data_record` 에서 사전 획득(6.3-4) |
| 실행 방법 | `control_model.exec_method` — `threshold`(내장 규칙) 또는 `llm_draft`(생성형 AI) |
| 출력 | `control_rule.draft_text` (자연어 초안) — **승인 전이므로 `action_json` 은 비어 있다** |
| 폴백 | AI 제공자 부재 시 `threshold` 로 자동 전환. 오프라인 동작이 깨지지 않는다 |

#### 4.4-b `fms.check_stale_devices(now) -> list[Alert]` (6.4-3 · A.1-4)

```python
def check_stale_devices(now: float) -> list[Alert]:
    """디바이스별 마지막 측정시각이 Period × 3 을 넘으면 alert 를 만든다.
       0937 6.4-3 — '정해진 시간에 데이터가 수집되지 않는 경우 알림 기능'"""
```

| 항목 | 값 |

| 기준 | `device_install_info` ↔ `env_state_data` 의 최신 `measured_at`. 상한은 `DEVICE_PROPERTY.Period × 3` |
| 호출 | I/O 스레드의 주기 틱 (아키텍처 §3.1-b). 프레임 수신과 무관하게 돈다 |
| `Keep Alive` 와의 차이 | Keep Alive 는 **노드 생존성**(8.2.1.5)이다. 노드가 살아 있고 특정 디바이스의 `NOTI_DEVICE_VALUE` 만 멈춘 경우는 Keep Alive 로 잡히지 않는다 — **두 감시가 모두 필요하다** |
| 배수 3 의 근거 | `Num. of Retry` 기본 3회(표 7-18). 재전송이 전부 실패해야 미수집으로 본다 |

### 4.5 후속 과제로 남긴 것

§5 참조. **6장의 `⚠` 6건 중 4건**과 **부속서 A 의 `⚠` 5건 중 2건**이 여기에 대응한다.
(F-094 — `⚠ 7건` 은 F-082 이전 수치였다. 정본 집계는 §1.7 · §3.5 다.)
