# rules.html 활용 가이드
## 1. 화면 목적과 안전 원칙

이 화면은 기상청 최고기온 기반 고온 관수 규칙 초안을 만들고 사람이 검토·승인한 뒤 실행하는 기능 데모다.
접속 주소는 `http://127.0.0.1:8000/rules.html`이다.
AI가 만드는 것은 설명용 `draft_text`뿐이며 승인 전에는 조건, 명령, 대상 장치와 실행 권한이 확정되지 않는다.

## 2. 입력 데이터 흐름

- 사용자는 화면에서 작물 고온 임계값만 입력한다.
- 예보 최고기온은 서버가 DMS의 최신 기상청 레코드에서 가져오며 직접 입력할 수 없다.
- 화면은 내부 고정값 `demo-model-llm-irrigation`을 제어 모델 ID로 전송한다.
- 권장 조치인 관수 장치 가동 문구는 등록된 제어 모델 메타정보에서 가져온다.
- AI에는 검증된 최고기온, 임계값, 권장 조치와 데이터 출처만 전달된다.

## 3. 실제 AI 성공 경로

1. 생성 방식에서 `AI_DRAFT`를 선택하고 작물 고온 임계값에 `33` 같은 숫자를 입력한다.
2. `초안 생성`을 누르고 저장된 카드에 `생성 경로: AI`가 표시되는지 확인한다.
3. AI가 작성한 한국어 초안이 예보 최고기온과 임계값을 근거로 삼는지 읽는다.
4. 카드가 `미승인`이고 실행 버튼 대신 사람 승인·거부 양식만 보이는지 확인한다.
5. 승인 전 API의 `action`, `target_install_id`, `approved_at`, `approved_by`가 모두 `null`인지 확인한다.
6. 승인 양식에서 조건·대상 구동기·명령 값·값 타입·선택적 구동 시간을 입력한다.
7. 승인 후에만 실행 버튼이 나타나고 실행 시 이력에 기록되는지 확인한다.

## 4. 오프라인 폴백 경로

프로세스를 종료하고 `.env`의 `OPENAI_API_KEY`를 비운다. 프로세스 환경변수로 키를 넣었다면 새 PowerShell을 연다.
README의 실행 절차에 따라 웹 서버를 다시 시작한다.

같은 임계값으로 초안을 만들면 `생성 경로: THRESHOLD_FALLBACK`과 임계값 기반 안내가 표시돼야 한다.
API 키나 네트워크가 없어도 초안 생성, 사람 승인과 실행 게이트는 계속 동작한다.

## 5. 승인·거부·실행 및 수동 제어

미승인 카드의 `승인하기`에서 구동기를 선택하면 허용 범위와 정밀도가 입력 힌트에 반영된다.
초안이 부적절하면 `거부하기`에서 필수 사유를 기록하며 거부된 규칙은 실행할 수 없다.
승인된 카드의 `실행`은 확정된 조건·명령·대상을 사용하고 결과를 실행 이력에 남긴다.
`수동/원격 제어`는 규칙과 별도의 직접 제어 경로이며 대상, 값, 값 타입과 선택적 시간을 입력한다.

## 6. 실패 진단

| 결과 | 확인할 항목 |
|---|---|
| `THRESHOLD_FALLBACK` | 키·모델 환경변수, HTTPS Base URL, 네트워크 연결 |
| HTTP 401 폴백 | API 키와 OpenAI 프로젝트 권한 |
| 모델 오류/404 폴백 | `OPENAI_MODEL`이 계정에서 사용 가능한 정확한 모델 ID인지 확인 |
| 타임아웃 폴백 | 네트워크 상태와 `OPENAI_TIMEOUT_SEC` 범위 확인 |

서버는 실패 종류와 상태만 기록하며 API 키, Authorization 헤더와 요청·응답 원문을 로그에 출력하지 않는다.

## 7. 완료 확인

- 공공데이터 출처가 표시되고 목업이면 `(더미데이터)`가 함께 표시된다.
- 카드에는 실제 생성 경로인 `AI` 또는 `THRESHOLD_FALLBACK`만 표시된다.
- 미승인·거부 규칙은 실행되지 않고 승인된 규칙에만 실행 버튼이 있다.
- 승인 실행과 수동 제어 결과가 실행 이력에 기록된다.
